### 1.2 What changes for users

After M1.6.3:

```sh
# Static cross-session aggregate TUI (deferred from M1.6.2)
agentprof aggregate --by tool --since 30d --export tui
agentprof aggregate --by day --since 7d --low-utilization-threshold 25 --export tui

# Live-refresh single-session TUI (NEW: notify-based file watcher)
agentprof watch                           # latest session, locked once attached
agentprof watch --session <UUID>          # specific session id
agentprof watch --agent copilot           # explicit agent (default copilot)

# Live-refresh cross-session aggregate TUI
agentprof watch aggregate --by tool --since 30d
agentprof watch aggregate --by day --low-utilization-threshold 25
```

The `watch` command auto-redraws within ~250 ms whenever the watched session file (or any session under the root, for the aggregate variant) is modified. Killer use case: "watch my Copilot session as it runs and see token cost / tool calls update live, without restarting the TUI."

## 2. Locked decisions (from brainstorming)

| # | Decision | Rationale |
|---|---|---|
| D-1 | **Ship both** `watch` + `aggregate --export tui` together (per user choice) | They share cross-session-aggregate code path (`watch aggregate` rebuilds an `AnyAggregateReport` on refresh, same shape that static `aggregate --export tui` consumes) |
| D-2 | `watch` is an **independent subcommand**, NOT a `--watch` flag on existing subcommands | Clear interaction semantics; future `--export md` + `--watch` combo would have undefined "write to file every refresh?" behavior |
| D-3 | Watch supports **both single-session AND cross-session** rendering | User choice — single = "look at the running session"; cross = "look at the running cost across all sessions". Both are valid real use cases |
| D-4 | Use **`notify = "7"` + `notify-debouncer-mini = "0.4"`** (Approach B), NOT polling | User choice — kernel-level (inotify/FSEvents/kqueue) means instant refresh + accurate event detection (rename / truncation / append all handled correctly). 2 new deps acceptable; both are MIT/Apache-2.0 |
| D-5 | `watch [--session latest]` mode **locks to initial session** after attach | User choice — explicit semantics; if user wants to follow a newer session, they `q` + restart. Auto-follow-latest needs a separate root-watcher + session-swap logic that's not worth it for MVP |
| D-6 | **Debounce window = 250 ms** | Matches TUI's existing `poll(Duration::from_millis(250))` cadence; coalesces typical append-burst storms (event-jsonl producers tend to flush every few ms) |
| D-7 | **New `WatchRunner` module** in `agentprof-tui` (coexists with M1.5 `AppRunner`) | Owned-data + reload-closure model is incompatible with M1.5 borrow-based `AppRunner`; cleaner to add a new sibling type than retrofit |
| D-8 | `WatchRunner` carries data via `enum WatchData { Single, Cross }` — single struct dispatches by variant | User choice — code reuse for the event loop, watcher channel, and refresh dispatch; render path matches on the variant to call existing view fns (Single) or new cross-session arm (Cross) |
| D-9 | Existing `agentprof-tui::views::aggregate` gets a **cross-session arm** alongside M1.5's by-mode + by-hook tables | User choice — extend rather than fork; one file with arm dispatch beats two files |
| D-10 | **Watcher thread lives in `agentprof-cli`**, NOT `agentprof-tui` | Watcher needs the `reload()` closure that calls `adapter.load_session + derive_episodes + analyze` — those types are in `agentprof-core` + `agentprof-adapters`. Putting watch in tui would force tui to depend on adapters (breaks lib leaf rule) |
| D-11 | **`Event::Refresh` variant** added to `agentprof-tui::app::event::Event` (alongside existing `Tick`/`Key`/`Resize`) | M1.5 already reserved `Tick #[allow(dead_code)]` for "watch mode periodic refresh"; instead of repurposing `Tick` (semantically wrong), add explicit `Refresh` that means "data changed; reload + redraw" |
| D-12 | Watch mode **requires TTY on both stdin + stdout** | Same as `analyze --export tui` (M1.5); piping the watch output is nonsensical |
| D-13 | **Reload failure surfaces in a footer banner**, watcher continues | A transient parse error (e.g., user wrote a half-line then flushed) shouldn't crash the watch session. Banner shows last error; cleared on next successful refresh |
| D-14 | **No real file-watcher integration test** in CI | notify+timing is flaky on CI runners. Cover with `assert_cmd` arg-parsing tests + manual smoke test in spec acceptance |
| D-15 | **No polling fallback** if notify init fails | YAGNI for MVP; print actionable error suggesting `--export md` and exit with `ExitKind::DataError`. Most platforms (Linux/macOS/Windows) have working notify backends |
| D-16 | New ADR-0009 documents the WatchRunner + notify design | Significant new public type + concurrency model warrants its own ADR |

## 3. Scope

### 3.1 In scope

1. **`agentprof aggregate --export tui`** — static cross-session TUI browser (deferred M1.6.2 feature)
2. **`agentprof watch` subcommand** with 2 sub-modes:
   - `watch [--session ID]` — single-session live TUI
   - `watch aggregate ...` — cross-session live TUI (reuses all `AggregateCmd` flags)
3. **`agentprof-tui::WatchRunner`** owned-data runner with optional refresh channel
4. **`agentprof-tui::app::event::Event::Refresh`** variant
5. **`agentprof-tui::views::aggregate`** cross-session arm + `render_cross_session` fn
6. **Watcher thread** in `agentprof-cli::cmd::watch` using `notify::RecommendedWatcher` + `notify-debouncer-mini`
7. **Reload closures**: `reload_single(adapter, sref) -> WatchData` and `reload_cross(adapter, root, agg_cmd) -> WatchData`
8. **Footer banner** for reload-error display
9. ADR-0009 documenting the design
10. L1 + L2 + L3 docs sync
11. ~10 tests (6 WatchRunner static + 2 cross-session view snapshot + cli arg-parse + parse_since reuse)

### 3.2 Out of scope

| Item | Why not |
|---|---|
| Drill-down from aggregate bucket → single session | Future M1.6.6; the cross-session aggregate view in watch mode is read-only |
| Auto-follow latest (root-watcher + session-swap) | D-5 — added complexity for niche use case |
| Polling fallback if notify fails | D-15 — YAGNI for MVP |
| Watcher reconnect on session-dir delete/recreate | Best-effort: log warning + continue; full reconnect deferred |
| Real file-watcher integration test in CI | D-14 — timing-flaky |
| `--watch` flag on existing subcommands (instead of separate `watch`) | D-2 — UX confusion |
| Per-session bell / notification on refresh | YAGNI |
| Pause/resume watcher (e.g. spacebar to freeze frame) | Future M1.6.6 |
| Watch mode for `list` subcommand | Not requested; users can `watch -n 1 agentprof list` if needed |

## 4. CLI surface

### 4.1 `agentprof watch` clap structure

```rust
// agentprof-cli/src/cmd/watch.rs

/// Live-refresh TUI: monitor session file(s) and redraw on change.
#[derive(Args, Debug, Clone)]
#[non_exhaustive]
pub struct WatchCmd {
    /// Aggregate sub-mode if specified; otherwise single-session.
    #[command(subcommand)]
    pub sub: Option<WatchSub>,

    /// Agent whose session to watch. M1.6.3 supports `copilot` only.
    #[arg(long, value_enum, default_value_t = AgentKind::Copilot)]
    pub agent: AgentKind,

    /// Override adapter's default session-state root.
    #[arg(long)]
    pub root: Option<PathBuf>,

    /// Which session to watch. Defaults to `latest`.
    #[arg(long, default_value = "latest")]
    pub session: SessionSelector,

    /// Debounce window (ms) for filesystem events.
    #[arg(long, default_value_t = 250)]
    pub debounce_ms: u64,
}

#[derive(Subcommand, Debug, Clone)]
#[non_exhaustive]
pub enum WatchSub {
    /// Watch cross-session aggregate (re-aggregates on any session change).
    Aggregate(crate::cmd::aggregate::AggregateCmd),
}
```

### 4.2 Behavior matrix

| Invocation | Watcher target | Reload | TUI runner |
|---|---|---|---|
| `agentprof watch` | `<root>/<latest-session-id>/events.jsonl` (single file) | re-parse + re-derive + re-analyze | `WatchRunner` (Single) |
| `agentprof watch --session <UUID>` | same, with explicit UUID | same | same |
| `agentprof watch aggregate --by tool` | `<root>/` (recursive, debounced) | re-discover sessions + re-aggregate | `WatchRunner` (Cross) |
| `agentprof watch aggregate --by day --since 7d` | same | same | same |
| `agentprof aggregate --by tool --export tui` (M1.6.2 was unsupported) | none | none — single load | `WatchRunner` (Cross, no refresh channel) |
| `agentprof watch --session=nonexistent` | rejected | n/a | exit `UserError` (1) |
| `agentprof watch` from non-TTY stdin or stdout | rejected | n/a | exit `OutputError` (3) with "watch requires TTY; use `analyze --export md` for headless" |

### 4.3 Exit codes

Unchanged from M1.4. Watch loop quits cleanly on `q` / Ctrl-C / `Action::Quit`. Watcher thread is terminated when the `WatchRunner` drops (mpsc receiver hangs up → debouncer thread exits).

### 4.4 `aggregate --export tui` activation

`AggExportFormat` enum (in `cmd::aggregate`) gains a `Tui` variant. Dispatch in `cmd::aggregate::run` routes to a new function that builds the `AnyAggregateReport` once and hands it to `WatchRunner::new_cross_static(any_report).run(...)`.

## 5. Data model

### 5.1 `WatchData` enum (in `agentprof-tui::watch`)

```rust
#[derive(Debug)]
#[non_exhaustive]
pub enum WatchData {
    /// Single-session TUI (analyze TUI surface).
    Single {
        report: agentprof_core::analyzer::AnalysisReport,
        episodes: agentprof_core::episode::Episodes,
        meta: agentprof_core::adapter::SessionMeta,
    },
    /// Cross-session aggregate TUI.
    Cross(agentprof_core::analyzer::aggregate::AnyAggregateReport),
}
```

Owns everything (vs M1.5 `AppRunner` which borrows). Required because reload swaps the data; borrowed lifetime would tie reload's output to the runner's lifetime.

### 5.2 `WatchRunner`

```rust
pub struct WatchRunner {
    /// Current data snapshot. Replaced on each refresh.
    data: WatchData,

    /// View / sort / scroll / selection state. Persists across reloads
    /// (sort key, selected row index, etc.).
    view_state: WatchViewState,

    /// Channel that the watcher thread writes to. None = static mode
    /// (no refresh; used by `aggregate --export tui` without watch).
    refresh_rx: Option<std::sync::mpsc::Receiver<RefreshKind>>,

    /// Closure that re-computes data on refresh. Used together with
    /// `refresh_rx`. None = static mode.
    reload: Option<Box<dyn FnMut() -> Result<WatchData, ReloadError>>>,

    /// Last reload error (footer banner). Cleared on next successful reload.
    last_error: Option<String>,

    /// Tick counter (informational; shown in footer "refreshes: N").
    refresh_count: u32,
}

#[derive(Debug, Clone)]
pub enum RefreshKind {
    /// One or more watched files changed.
    DataChanged,
}

#[derive(thiserror::Error, Debug)]
pub enum ReloadError {
    #[error("session disappeared at {path}")]
    SessionGone { path: PathBuf },
    #[error("reload pipeline failed: {0}")]
    Pipeline(#[from] anyhow::Error),
}
```

### 5.3 `WatchViewState`

Owned analogue of the existing `AppState`. Stores user-driven view state that persists across reloads (so a sort key doesn't reset every 250 ms during active typing):

```rust
pub struct WatchViewState {
    pub view: View,
    /// Sort key for cross-session aggregate view.
    pub agg_sort: AggSortKey,
    /// Selected bucket row.
    pub agg_selected: usize,
    /// (Single-session views): reuse M1.5 state fields by composition.
    pub single: Option<SingleViewState>,
    /// Show help overlay (?).
    pub help_overlay: bool,
}

pub enum AggSortKey { Calls, TotalDuration, Sessions, Percentile50 }
```

### 5.4 `Event::Refresh` (in `agentprof-tui::app::event::Event`)

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Event {
    Key(KeyEvent),
    Resize(u16, u16),
    #[allow(dead_code)] Tick,
    /// M1.6.3 — emitted by WatchRunner's refresh path. NOT produced by
    /// the static AppRunner.
    Refresh,
}
```

The existing `from_crossterm` doesn't produce `Refresh` (it only comes from `refresh_rx` in `WatchRunner::run`).

## 7. File-watcher implementation

### 7.1 Single-session

```rust
// agentprof-cli/src/cmd/watch.rs
fn spawn_single_watcher(
    file: PathBuf,
    debounce: Duration,
    tx: mpsc::Sender<RefreshKind>,
) -> Result<Debouncer<RecommendedWatcher>, WatchInitError> {
    let debouncer = new_debouncer(debounce, move |result: DebounceEventResult| {
        match result {
            Ok(events) if !events.is_empty() => {
                let _ = tx.send(RefreshKind::DataChanged);
            }
            Ok(_) => {}  // empty
            Err(errors) => {
                tracing::warn!(?errors, "notify debouncer errors");
            }
        }
    })?;
    debouncer.watcher().watch(&file, RecursiveMode::NonRecursive)?;
    Ok(debouncer)
}
```

### 7.3 Reload closures

```rust
// agentprof-cli/src/cmd/watch.rs

fn make_single_reload(
    adapter: CopilotAdapter,
    sref: SessionRef,
) -> impl FnMut() -> Result<WatchData, ReloadError> {
    move || {
        let raw = adapter.load_session(&sref).map_err(...)?;
        let episodes = derive_episodes(&raw.events, &raw.meta);
        let report = analyze(&episodes, &raw.meta, &raw.parse_warnings);
        Ok(WatchData::Single { report, episodes, meta: raw.meta })
    }
}

fn make_cross_reload(
    adapter: CopilotAdapter,
    agg_cmd: AggregateCmd,
) -> impl FnMut() -> Result<WatchData, ReloadError> {
    move || {
        // Reuse the same pipeline as cmd::aggregate::run, but return the
        // AnyAggregateReport instead of rendering. Factor cmd::aggregate
        // to expose a `compute_aggregate(cmd) -> Result<AnyAggregateReport>`
        // helper so both static + watch use the same path.
        Ok(WatchData::Cross(compute_aggregate(&adapter, &agg_cmd)?))
    }
}
```

This requires a small refactor of `cmd::aggregate::run` — extract the "compute" half into a shared `compute_aggregate` function. The "render + write" half remains in `run`.

### 7.4 Watcher lifecycle

The debouncer is **kept alive** for the duration of `WatchRunner::run` by the cli's `run` function:

```rust
let _watcher = spawn_single_watcher(file, ..., tx)?;
let mut runner = WatchRunner::with_watcher(rx, reload_closure);
runner.run(terminal)?;
// _watcher drops here, debouncer thread cleans up
```

Dropping the debouncer hangs up `tx`; runner's `try_recv` returns `Disconnected` (treated same as "no events for now"). Clean shutdown.

## 8. View extensions

### 8.1 `aggregate::render_cross_session`

New function in `agentprof-tui::views::aggregate`:

```rust
pub fn render_cross_session(
    frame: &mut Frame<'_>,
    area: Rect,
    report: &AnyAggregateReport,
    sort: AggSortKey,
    selected: usize,
) {
    // Single-screen layout:
    //   Top:    header bar (by / sessions / window / refresh_count)
    //   Middle: bucket table (per --by key; columns per spec)
    //   Bottom: footer (sort key indicator + key bindings hint + last_error if present)
}
```

Sort key cycling (`c` / `t` / `s` / `p`) re-sorts buckets in place; cursor stays at the same RELATIVE row (or row 0 if list shrunk).

### 8.2 `dispatch` extension

`agentprof-tui::app::state::dispatch(state, event)` gains awareness of `Event::Refresh` (no-op for the dispatch state machine; refresh handling is in `WatchRunner::run` outside dispatch). The key bindings for aggregate cross-session:

| Key | Action |
|---|---|
| `q` / Esc / Ctrl-C | Quit |
| `?` | Toggle help overlay |
| `1` / `2` / `3` | (single-session only) View switch |
| `c` | (cross-session) Sort by call_count |
| `t` | (cross-session) Sort by total_duration |
| `s` | (cross-session) Sort by session_count |
| `p` | (cross-session) Sort by p50_duration (or fallback for non-Tool) |
| `↑` / `↓` | Move selected row |
| `Home` / `End` | Jump to first / last |
| `PgUp` / `PgDn` | Scroll page |

### 8.3 Footer banner

When `last_error.is_some()`, render a 1-line footer in red:

```
⚠ reload error: cannot parse events.jsonl at <path>; watching anyway
```

Cleared on next successful reload.

## 14. Risks & follow-ups

### 14.1 Risks (with mitigations)

| Risk | Mitigation |
|---|---|
| `notify` Artistic-2.0 license not in deny allowlist | Verify in T2; add to deny.toml if needed (permissive, OSI-approved) |
| Debouncer fires no events on some CI runner (no inotify support) | D-14 — manual smoke; CI relies on unit-level tests not running actual watcher |
| Reload closure captures adapter by value — adapter is unit struct so this is free | ✓ verified (CopilotAdapter is zero-sized) |
| Refresh fires while user is mid-keystroke (sort key cycling) | Loop iterates: redraw → check refresh → poll key. Refresh just replaces data; sort key + selected row preserve from view_state |
| Watcher hangs after session-dir deletion | Debouncer reports error; banner shows it; user manually `q`s |
| 100+ sessions in cross-session watch → reload takes 10+ seconds | Each refresh blocks the TUI for ~10s during reload; acceptable for MVP. Future M1.6.6 perf milestone could move reload off the TUI thread |
| Reload error in `analyze` pipeline (e.g. corrupt JSONL mid-write) | Banner shows error; data not swapped; next refresh tries again |

### 14.2 Deferred follow-ups (M1.6.6+ candidates)

1. Drill-down from cross-session bucket → single-session analyze TUI
2. Auto-follow latest session (root-watcher + session-swap)
3. Polling fallback if notify fails
4. Pause/resume watcher (spacebar to freeze)
5. Watch refresh on background thread (don't block TUI during reload)
6. Per-session bell on append
7. Show watcher status (active / paused / disconnected) in footer
8. Watch mode for `list` subcommand
9. `--watch` flag on `analyze` / `aggregate` (alternative UX surface)

## 16. Glossary

- **WatchRunner**: new TUI runner in `agentprof-tui::watch`; owns its data (unlike borrow-based `AppRunner`); has optional refresh channel for watch mode
- **WatchData**: enum carrying either Single (analyze TUI data) or Cross (aggregate TUI data)
- **Refresh channel**: `mpsc::Receiver<RefreshKind>` that the notify watcher thread writes to; the WatchRunner drains non-blocking each loop iteration
- **Debouncer**: `notify-debouncer-mini` coalesces a burst of filesystem events into one debounced event (default 250 ms)
- **Reload closure**: `Box<dyn FnMut() -> Result<WatchData, ReloadError>>` — captures adapter + session metadata; called on each refresh
- **Footer banner**: 1-line at bottom of TUI showing last reload error in red; cleared on next successful reload
- **Single-session mode**: `watch [--session ID]` — watches one `events.jsonl` file; reload = parse + derive + analyze; renders existing M1.5 views
- **Cross-session mode**: `watch aggregate --by KEY` — watches the root dir recursively; reload = discover + load N sessions + aggregate; renders new cross-session aggregate view
