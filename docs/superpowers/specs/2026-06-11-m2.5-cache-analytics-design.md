## 1. Problem statement

Anthropic prompt caching (and the analogous OTel `gen_ai.token.type =
{cache_creation, cache_read}` signals) emit per-request token counts
that AgentProf already captures end-to-end:

- Copilot adapter writes `cache_read_tokens` (and absent cache_creation;
  Copilot's wire format gives one number labeled "cacheReadTokens").
- OTLP `sink_storage::map_token_point` accumulates both directions.
- `agentprof_core::analyzer::ModelUsage` carries `cache_read_tokens`
  and `cache_creation_tokens` (both `u64`).
- `AnalysisReport::total_cache_read()` + `total_cache_creation()`
  accessors aggregate over `model_metrics`.
- SQLite schema stores `sessions.total_cache_read` / `total_cache_creation`
  (M2.1 migration `001_initial.sql:20-21`) and `model_metrics.cache_read`
  / `cache_creation` (lines 46-47).
- TUI Models view (`crates/agentprof-tui/src/views/models.rs`) already
  displays per-model `cache_read` in its table (line 135) and totals
  row (line 145).

**Gap**: every other render surface is silent on cache.

- `analyze --export md / html / json / csv` — no cache section, no field.
- `list` — no cache column.
- `aggregate --by model / day / tool / mcp-server` — no cache column.

This is **audit finding F-NEW-2** ("6 write-only schema columns")
under a different name; the columns are written and stored, but nothing
shows them to users outside the TUI Models view.

This spec closes:
- `docs/architecture.md` §18 Q4a (observational cache analytics).
- Audit F-NEW-2 (read-path wire-up for cache_creation / cache_read).

Q4b (prompt-prefix recommendation engine) is **out of scope** — see
post-v0.3.1 §18 update.

## 2. Scope

### In scope

- New core module `analyzer::cache` defining `CacheMetrics` struct and
  the canonical hit-rate / saved-token formulas (two each: "naive"
  + "honest"; see §3 D-2).
- `AnalysisReport::cache_metrics()` accessor (returns `None` if zero
  cache activity).
- `AggregateReport::cache_metrics_per_bucket()` for `--by model` and
  `--by day` modes; explicit `None` / absence for `--by tool` and
  `--by mcp-server` (cache tokens are prompt-level, not attributable
  per-tool).
- Render-side wire-up to 7 surfaces (analyze md/html/json/csv + list
  + aggregate --by model + aggregate --by day) + a small consistency
  update to the existing TUI Models view (add NetSaved column).
- ~25 new tests (unit + insta snapshots).
- ADR-0023 codifying the formula choices + the per-tool /
  per-mcp-server "no cache columns" policy.
- L1 + L2 doc sync.

### Out of scope (deferred)

- **Q4b prompt-prefix recommendation engine** — separate trigger criteria
  in `docs/architecture.md` §18 update.
- **Translating saved tokens to dollars** — requires per-model
  pricing table + Anthropic pricing-change tracking SLA. Could be
  M3.3 (already on `docs/plan.md` §7.2 list).
- **SQLite schema additions** — none needed; all required data
  already in M2.1 + M2.x columns.
- **Cache analytics in `mcp-waste`** — MCP server cache attribution
  has the same prompt-level vs tool-level mismatch as `aggregate
  --by mcp-server`; the existing `mcp-waste` view stays unchanged.
- **Anthropic-specific cache strategy hints** ("you should set
  cache_control on this prompt prefix") — that's Q4b.

## 3. Design decisions

### D-1 — Compute centrally, render distributed

New module `crates/agentprof-core/src/analyzer/cache.rs` owns the math.
Each render surface (md/html/json/csv/list/aggregate/TUI) reads the
`CacheMetrics` struct and formats; no surface re-implements the
formulas.

**Rationale**: prevents formula drift across surfaces; single point of
test coverage; ADR-0023 documents the canonical formulas so any
divergence is a visible bug.

**Alternatives considered**:
- **Inline at each surface** — smaller diff, but every md/html/json/csv
  callsite would re-derive the formulas, guaranteeing drift over time.
- **Hybrid (core math + macro-based render)** — macros obscure the
  render code more than they help; readability cost outweighs the
  consistency win the centralized struct already provides.

### D-2 — Show both naive and honest hit-rate / saved-token formulas

```text
hit_rate_naive_pct  = 100 * cache_read / (cache_read + input_tokens)
hit_rate_honest_pct = 100 * cache_read / (cache_read + cache_creation)
saved_gross         = round(cache_read * 0.9)
saved_net           = round(cache_read * 0.9 - cache_creation * 0.25)
```

- **Naive** = "of all prompt tokens I sent, X% came from cache"
  (intuitive — most users mean this when they say "hit rate").
- **Honest** = "of the work I tried to cache, X% paid off" (real
  signal — exposes high-create-low-read mis-strategies).
- **Gross saved** = cache read discount only.
- **Net saved** = cache read discount − cache write premium (can go
  negative when creation dominates).

Show **honest as primary** + **naive as supplement**. Users see "55%
honest / 78% naive" and learn quickly that high naive + low honest =
"you're benefiting but inefficient"; low both = "cache strategy
broken"; high both = ideal.

Constants live in `analyzer::cache`:
- `CACHE_READ_DISCOUNT: f64 = 0.9`
- `CACHE_WRITE_PREMIUM: f64 = 0.25`

These are Anthropic's published Claude Sonnet 4.x rates. Codified in
the ADR + the source constant; **change this** requires a CHANGELOG
breaking-flag because saved_net flips sign.

**Alternatives considered**:
- **Naive only** — simpler, but hides over-caching anti-patterns.
- **Honest only** — confuses users who expect the intuitive formula.
- **Single "effectiveness" composite metric** — opaque; users can't
  decompose the signal.

### D-3 — No cache columns for `--by tool` and `--by mcp-server`

Cache tokens are accumulated **per API call** (per turn / per request),
not per tool invocation. A single API call's `cache_read = 8K` might
serve 3 tool calls within that turn; there is no defensible attribution
formula.

For `aggregate --by tool` and `--by mcp-server`:
- Result tables **omit** cache columns entirely (same column set as
  M1.6.x).
- `AggregateReport::cache_metrics_per_bucket()` returns `None` for
  these modes; render skips the cache section.
- README footnote + ADR-0023 spell out the rationale so future
  contributors don't add "—" cells "for symmetry".

For `aggregate --by model` and `--by day`:
- Bucket key is at least as coarse as a session; per-session cache
  totals fit exactly. Cache columns ON.

**Alternatives considered**:
- **N/A cells in tool/mcp-server tables** — table-shape symmetry but
  every cell becomes noise; users start ignoring the column.
- **Naive proportional attribution** (cache_read / tool_calls per
  turn) — quantitatively misleading. Users would make decisions on
  fictional data.

### D-4 — `None`-on-zero-activity semantics

`AnalysisReport::cache_metrics()` returns `None` when both `creation
== 0` and `read == 0`. Render layer omits the cache section / column
entirely (cleaner than a table full of `0` / `0.0%`).

For aggregate buckets with mixed cache / no-cache sessions, the bucket
is `Some(metrics)` if any session contributed; per-session zero rows
silently sum into the bucket totals.

### D-5 — Render formats

#### Single-session (`analyze`)

- **md** — new `## Cache` section between the existing Model section
  and any subsequent section. Markdown table with columns:
  `Metric | Creation | Read | Hit% (honest) | Hit% (naive) | Saved gross | Saved net`.
  Two rows: per-session total + per-model breakdown (one row per
  model if `> 1` model).
- **html** — same content, new `<section id="cache">` in
  `templates/report.html`. CSS reuses existing `.metrics-table`.
- **json** — top-level field `"cache_metrics": <CacheMetrics> | null`.
  Schema additive; existing tooling unaffected.
- **csv** — 4 new columns appended after current last column:
  `cache_creation, cache_read, hit_pct_honest, saved_net`.
  (Gross + naive are JSON / md / html only; CSV stays compact for
  spreadsheet import.)

#### Multi-session (`list`, `aggregate`)

- `list` — 1 new column `Cache%` between `Out-tokens` and `Duration`.
  Shows `hit_pct_honest` with 1 decimal place, or empty cell on
  `None`.
- `aggregate --by model` — 4 new columns after the existing `Tokens`
  column: `CacheCr | CacheRd | Hit% | NetSaved`.
- `aggregate --by day` — same 4 columns.

#### TUI Models view

Already shows raw `cache_read` per model + totals (M1.6.x).
Add 1 new column `NetSaved` to the right of the existing
`cache_read` column. No new view; minimal incremental change.

### D-6 — JSON field naming convention

`"cache_metrics"` (snake_case) on top-level `AnalysisReport` JSON.
Mirror naming for aggregate JSON: `"buckets": [{ ..., "cache_metrics":
{...} | null }, ...]`.

Existing top-level fields are snake_case already (`total_input_tokens`,
`total_output_tokens`). Consistent.

## 4. API additions

All additive; zero breaking changes.

### 4.1 `agentprof_core::analyzer::cache::CacheMetrics`

```rust
#[non_exhaustive]
#[derive(Debug, Clone, Copy, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct CacheMetrics {
    pub creation: u64,
    pub read: u64,
    pub input: u64,
    pub hit_rate_naive_pct: f64,
    pub hit_rate_honest_pct: f64,
    pub saved_gross: u64,
    pub saved_net: i64,
}

pub const CACHE_READ_DISCOUNT:  f64 = 0.9;
pub const CACHE_WRITE_PREMIUM:  f64 = 0.25;
```

`#[non_exhaustive]` per project rule §7-5 + the v0.3.1 audit
F-NEW-4 sweep precedent.

### 4.2 Accessors

```rust
impl AnalysisReport {
    /// Returns None when the session had zero cache activity.
    pub fn cache_metrics(&self) -> Option<CacheMetrics>;
}

impl AggregateReport {
    /// Returns Some(metrics) per bucket key for --by model / --by day.
    /// Returns None for --by tool / --by mcp-server (cache tokens are
    /// prompt-level; not attributable per-tool). See ADR-0023.
    pub fn cache_metrics_per_bucket(&self) -> Option<HashMap<String, CacheMetrics>>;
}
```

### 4.3 No new public types beyond `CacheMetrics`

Render code uses the struct directly; no helper trait.

## 8. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Anthropic pricing constants drift (0.9 / 0.25 stale) | Constants centralized + ADR-0023 calls them out as "Claude Sonnet 4.x rates as of 2026-06"; change triggers CHANGELOG `BREAKING:` for saved_net flip |
| `saved_net` negative confuses users | Render shows `-X tokens` clearly; ADR-0023 + README explain it's intentional ("you may be over-caching") |
| Aggregate `cache_metrics_per_bucket()` Option semantics get awkward | Two layers: outer Option = "this report kind supports cache attribution"; inner Option per-bucket = "this bucket had any activity". Outer `None` for tool/mcp-server modes guarantees render never even iterates. |
| Float arithmetic in formulas → snapshot drift | `f64` only used for hit_rate_*_pct (1-decimal render avoids fp surprises); saved_gross/net stay integer (rounding done at compute time) |
| TUI Models view layout breaks with NetSaved column on small terminals | Reuse existing column-elide logic (M1.6.x established pattern); fall back to dropping NetSaved before dropping cache_read |
| Q4b sneaks back in as scope creep | Spec explicit + ADR-0023 explicit: this is observational only; no recommendation logic, no $-translation, no algorithms over prompt content |
