> **Date:** 2026-06-03.
> **Pipeline stage:** 1 (Discovery / Design). Next: Stage 2 (ADR-0012 — see §10) then Stage 3 (writing-plans).
> **Author:** Copilot brainstorming session 252068e5.

---

## 1. Why

F1.6 surfaced per-turn `Turn.output_tokens` in FlamegraphView prefix + TurnDetailView header. User followed up immediately: "input tokens and cache tokens?"

Empirical survey of real Copilot CLI sessions (2026-06-03, session `252068e5-…`):

| Token type | Available at | Per-turn? |
|---|---|---|
| Output tokens | `assistant.message.outputTokens` | ✅ Already used (F1.6) |
| Input tokens | `session.shutdown.modelMetrics[model].usage.inputTokens` | ❌ Only session-level totals |
| Cache-read tokens | `session.shutdown.modelMetrics[model].usage.cacheReadTokens` | ❌ Only session-level totals |
| Cache-write tokens | `session.shutdown.modelMetrics[model].usage.cacheWriteTokens` | ❌ Only session-level totals |
| Compaction tokens | `session.compaction_complete.compactionTokensUsed.{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens}` | Per-compaction-event |

**Key finding**: Copilot CLI **does not expose per-turn input/cache tokens** on the wire. They only land in session-level totals on `session.shutdown` and in per-compaction-event totals. Per-turn estimation via `session.compaction_start.conversationTokens` diffing is possible but lossy (and only fires at compaction boundaries).

**Decision**: ship session-level model usage as a separate "Models" TUI view rather than synthetic per-turn estimation. Real data, no inference.

## 2. What — User-facing contract

### 2.1 New TUI view

New top-level view in `AppRunner`:

- **Key `4`** switches to `View::Models` (was unbound before).
- `Tab` / `Shift-Tab` cycles include the new view.
- Help overlay (`?`) lists `4` as a view-switch key.

### 2.2 Models view layout

When session has `model_metrics` data (i.e. `session.shutdown` event was emitted):

```
┌ Models — session token usage ────────────────────────────────────────────────┐
│ Model                                  Input     Output     Cache R   Cache W│
│ ────────────────────────────────────────────────────────────────────────────│
│ claude-opus-4.7-1m-internal           98k        47k        3.4M      721k  │
│ gpt-5-mini                            781k       18k        499k      0     │
│ gemini-2.5-pro                        12k        5k         0         0     │
│ ────────────────────────────────────────────────────────────────────────────│
│ Total                                 891k       70k        3.9M      721k  │
│                                                                              │
│ session has 3 models · sorted by input desc · Esc switches to view 1         │
└──────────────────────────────────────────────────────────────────────────────┘
```

Sort by `inputTokens` descending. No interactive resort in v1.

Token formatting reuses `format_tokens_short` (5-char cap) from F1.6's `views::format`. Width-budget grows for the "Total" footer line.

### 2.3 Empty-state (no shutdown event)

When session has NO `session.shutdown` event (live mode, crashed session, or pre-shutdown midway through):

```
┌ Models — session token usage ────────────────────────────────────────────────┐
│                                                                              │
│         (no model usage data — session has not emitted shutdown event yet)   │
│                                                                              │
│         Token totals are reported on `session.shutdown`. If you're in        │
│         live watch mode, wait for the agent to exit (or hit Ctrl-D).         │
│                                                                              │
│                              Esc switches to view 1                          │
└──────────────────────────────────────────────────────────────────────────────┘
```

Centered placeholder + explanation + `Esc` hint. Same convention as TurnDetailView's `(turn not found)` / `(no tool calls)` placeholders.

### 2.4 Key bindings in Models view

| Key | Action |
|---|---|
| `Esc` | Switch to `View::Flamegraph` (view 1) — convention shortcut for "back" |
| `1` / `2` / `3` / `4` | Switch to corresponding top-level view |
| `Tab` / `Shift-Tab` | Cycle views |
| `q` / Ctrl-C | Global quit |
| `?` | Help overlay |
| `↑` / `↓` / `j` / `k` | Move row selection (visual highlight; no functional impact in v1) |
| `G` / `gg` | Jump to last/first row |

`Enter` is reserved (does nothing in v1; could open per-model drill-down in F2.x).

### 2.5 Aggregate view consistency

`AggregateView` (existing single-session aggregate, key `3`) does NOT change. Model metrics are a session-level rollup distinct from the per-tool/per-MCP/per-day/per-model aggregates over `Episodes` content.

### 2.6 Watch mode

`WatchRunner` (single-session live mode) supports the new view via the existing transient-AppState round-trip. When `session.shutdown` finally arrives (file appended on agent exit), the next reload populates `AnalysisReport.model_metrics`; Models view body switches from empty-state to the table on the next render.

Cross-session aggregate mode (`watch aggregate ...`) does NOT support `View::Models` (it's per-session data and cross-session aggregation would need a separate design).

## 3. Architecture

### 3.1 Data flow

```
Copilot adapter                  agentprof-core derive_episodes              agentprof-tui
─────────────────                ───────────────────────────────              ──────────────
SessionShutdown event            Event::payload_model_metrics() ──┐
  .modelMetrics                                                    │
  [model].usage:                                                   │
    inputTokens                                                    ▼
    outputTokens          ─────►  PASS 0' (analyzer.rs):
    cacheReadTokens               for ev in events:
    cacheWriteTokens                if let Some(m) = ev.payload_model_metrics():
                                      report.model_metrics = Some(m);
                                                                   │
                                                                   ▼
                                              AnalysisReport.model_metrics
                                                                   │
                                                                   ▼
                                                          render_models reads
                                                          app_state.report.model_metrics
                                                          → table or empty-state
```

### 3.2 `agentprof-core` changes

**File: `crates/agentprof-core/src/analyzer/mod.rs`** — add new public struct + field on `AnalysisReport`:

```rust
/// Per-model token-usage rollup, sourced from
/// `session.shutdown.modelMetrics` (Copilot CLI). All fields default to
/// 0 when the wire format omits them.
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[non_exhaustive]
pub struct ModelUsage {
    /// Input (request prompt) tokens.
    pub input_tokens: u64,
    /// Output (response generation) tokens.
    pub output_tokens: u64,
    /// Cache-read tokens (re-used context).
    pub cache_read_tokens: u64,
    /// Cache-write tokens (new context entered into the prompt cache).
    pub cache_write_tokens: u64,
}

impl ModelUsage {
    /// Construct a zero-initialized usage rollup.
    #[must_use]
    pub const fn new() -> Self { /* all fields = 0 */ }

    /// Total of all four token categories. Convenience for sorting + footer.
    #[must_use]
    pub const fn total(&self) -> u64 {
        self.input_tokens
            .saturating_add(self.output_tokens)
            .saturating_add(self.cache_read_tokens)
            .saturating_add(self.cache_write_tokens)
    }
}
```

```rust
// modification to existing AnalysisReport struct:
#[non_exhaustive]
pub struct AnalysisReport {
    pub meta: SessionMeta,
    pub turn_summary: Vec<TurnSummaryRow>,
    pub tool_rank: Vec<ToolRankRow>,
    pub hook_rank: Vec<HookRankRow>,
    pub warnings: Vec<DeriveWarning>,
    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    pub parse_warnings: Vec<ParseWarning>,
    /// Per-model token usage rollup, populated from
    /// `Event::payload_model_metrics()`. `None` when no event provided
    /// the data (e.g. session without `session.shutdown`).
    /// Map key is the model identifier as reported by the adapter.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub model_metrics: Option<std::collections::BTreeMap<String, ModelUsage>>,
}
```

`AnalysisReport::new(meta)` ctor defaults `model_metrics: None`.

**File: `crates/agentprof-core/src/adapter.rs`** — add to `pub trait Event`:

```rust
/// Adapter-specific per-model token-usage rollup, when the event
/// reports it (e.g. Copilot's `session.shutdown`). Returns `None`
/// for events without the data.
///
/// Used by `analyze()` to populate
/// [`crate::analyzer::AnalysisReport::model_metrics`]. Default returns
/// `None`; adapters override for variants that carry the data.
///
/// Singular semantics — when multiple events emit non-None values
/// in the same session (unusual but possible), `analyze()` keeps the
/// LAST seen (matches the existing "last-wins" rule used for
/// [`crate::episode::Turn::model`]).
fn payload_model_metrics(&self) -> Option<std::collections::BTreeMap<String, ModelUsage>> {
    None
}
```

**File: `crates/agentprof-core/src/analyzer/mod.rs`** — modify `pub fn analyze` to populate the new field:

```rust
pub fn analyze(
    episodes: &Episodes,
    meta: &SessionMeta,
    parse_warnings: &[ParseWarning],
) -> AnalysisReport {
    // existing rollups ...
    AnalysisReport {
        /* existing fields */,
        model_metrics: None, // populated by `analyze_with_events` below
    }
}
```

> **Design alt (decided)**: `analyze()` takes `&Episodes`, not `&[Event]`. To populate `model_metrics` we'd need event access — either:
>
> - (i) Add a new public fn `analyze_with_events(events, episodes, meta, parse_warnings)` that supplements `analyze()`.
> - (ii) Move the `payload_model_metrics` pass UP into the caller (cli/adapter level) and store the result on `SessionMeta` (revising Q1's decision).
> - (iii) Add `Episodes.model_metrics: Option<BTreeMap<...>>` and populate in `derive_episodes` PASS 0 (matches F1 ToolCall.arguments pattern). Then `analyze()` clones it into the report.
>
> **(iii) chosen** — minimizes API surface (no new `analyze_*` fn), reuses the F1 PASS 0 collection pattern, and keeps `Episodes` as the canonical event-derived bundle. `Episodes.model_metrics` flows naturally into `AnalysisReport.model_metrics` via `analyze()`.

Updated approach: `Episodes` gains `pub model_metrics: Option<BTreeMap<String, ModelUsage>>`; `derive_episodes` PASS 0 (or PASS 1) populates it (last-wins on duplicate emitters); `analyze()` clones it into `AnalysisReport.model_metrics`.

### 3.3 `agentprof-adapters` changes

**Discovery (spec self-review):** `CopilotEvent::Shutdown(WithEnvelope<ShutdownData>)` variant **already exists** at `crates/agentprof-adapters/src/copilot/event.rs:91-92`. `ShutdownData.model_metrics: BTreeMap<String, serde_json::Value>` (line 281) holds the raw per-model rollup as free-form `Value` (because the wire shape varies across Copilot versions). No new variant + struct work needed.

**File: `crates/agentprof-adapters/src/copilot/event.rs`** — implement `payload_model_metrics` on `CopilotEvent` (inherent method + trait override), walking the existing `serde_json::Value` shape:

```rust
fn payload_model_metrics(&self) -> Option<BTreeMap<String, ModelUsage>> {
    let Self::Shutdown(env) = self else { return None };
    let mut out = BTreeMap::new();
    for (model, metrics_value) in &env.data.model_metrics {
        // `metrics_value.usage` holds the input/output/cache rollup;
        // skip models whose usage subtree is absent.
        let usage = metrics_value.get("usage")?;
        let read_u64 = |key: &str| -> u64 {
            usage.get(key).and_then(serde_json::Value::as_u64).unwrap_or(0)
        };
        out.insert(model.clone(), ModelUsage {
            input_tokens: read_u64("inputTokens"),
            output_tokens: read_u64("outputTokens"),
            cache_read_tokens: read_u64("cacheReadTokens"),
            cache_write_tokens: read_u64("cacheWriteTokens"),
        });
    }
    if out.is_empty() { None } else { Some(out) }
}
```

Single-line caveat: if a model has `metrics_value.usage` missing entirely (e.g. shutdown emitted without successful API calls for that model), the `get("usage")?` short-circuits the closure but the `for` loop's `?` would early-return; rewrite to `continue` on `None`:

```rust
let Some(usage) = metrics_value.get("usage") else { continue };
```

> **Risk reduction**: this design is robust against Copilot wire format changes — adding new fields under `usage` doesn't break parsing; field renames just produce `0` instead of failing.

## 6. Out of scope (deferred)

- **Per-turn input/cache tokens** — Copilot wire doesn't expose this. Possible via `session.compaction_start.conversationTokens` diffing, but lossy. Reserved for a future "Phase C" design.
- **Per-token cost in $** — needs model pricing table. M2 territory.
- **Compaction event history view** — `session.compaction_complete` carries useful per-compaction data; could be a separate "Compactions" view (key `5`?). Deferred.
- **Cross-session aggregate of model usage** — `watch aggregate ...` doesn't get Models view; out of scope.
- **Per-model drill-down** — Enter on a Models row could open a per-model detail (e.g. requests count over time). Deferred; F2.x territory.
- **Token rate metrics** (tokens/sec, prompt-throughput) — derivable from `output_tokens / turn.duration` but out of scope here.
- **`session.compaction_start.conversationTokens` rolling line in Models view** — would show the conversation token trajectory across compaction events. Deferred.

## 7. Alternatives considered

| Q1 alternative (where to store ModelUsage) | Verdict |
|---|---|
| `SessionMeta` | ❌ — SessionMeta is for input metadata; ModelUsage is derived/analysis output |
| **`AnalysisReport`** | ✅ — parallels existing `tool_rank` / `hook_rank` rollups |
| New `SessionTotals` top-level struct | ❌ — adds another consumer surface for no gain |

| Q2 alternative (adapter exposure) | Verdict |
|---|---|
| `Adapter::parse_model_metrics(session)` | ❌ — breaks the `Event` trait contract used elsewhere |
| **`Event::payload_model_metrics()`** | ✅ — symmetric with 5 existing `payload_*` methods (ADR-0005 + ADR-0011 precedent) |
| Adapter pre-attaches to `RawSession` | ❌ — pollutes RawSession with derived data |

| Q3 alternative (empty-state UX) | Verdict |
|---|---|
| Empty table + footer hint | ❌ — user might miss the hint and think the binary is broken |
| Snap back to prev view | ❌ — key feels broken |
| **Centered placeholder + explanation** | ✅ — consistent with TurnDetailView empty-state convention |

## 8. Risks

- **`session.shutdown` adapter variant already exists** (spec self-review finding) — `CopilotEvent::Shutdown(WithEnvelope<ShutdownData>)` at line 91-92 with `model_metrics: BTreeMap<String, serde_json::Value>` at line 281. Just need to add `payload_model_metrics()` impl; no new variant work.
- **`derive_episodes` PASS 0 vs PASS 1 ordering** — model_metrics population can be in either pass. We picked PASS 1 (state-machine arm for `EventKind::SessionShutdown`) since it's last-wins by event order and naturally fits the existing state machine. Verify this doesn't break ADR-0004's "pure + total" guarantees (it doesn't — adding a state-machine arm is still pure + total).
- **TUI key 4 collision** — `4` was previously unbound at the top level. Verify by reading `dispatch` body (currently 1/2/3 only).
- **Wide-char model names** — `claude-opus-4.7-1m-internal` is 28 ASCII chars; longest model names in practice are ~40. Column widths in the Models table need to accommodate. Use `width.saturating_sub(...)` math similar to FlamegraphView.
- **`Episodes.model_metrics` clone in `analyze()`** — `BTreeMap<String, ModelUsage>` is small (max ~10 models per session × ~32 bytes each ≈ 320 bytes). Clone cost negligible.
