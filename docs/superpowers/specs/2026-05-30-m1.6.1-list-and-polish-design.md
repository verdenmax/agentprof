## 0. TL;DR

`agentprof list` discovers Copilot sessions and prints a 7-column table (`ID / Started / Model / Turns / Out-tokens / Duration / Size`) with `--limit 20 --since 7d` defaults. Plain-text padding, zero new deps. Full per-session analyze (≈ a few seconds for default limit). Single-session parse failures degrade gracefully (skipped, summarized to stderr).

Plus 8 audit-driven polish items addressing performance, API encapsulation, Windows kitty-protocol compatibility, UX clarity, dead-code, fixture quality, and doc accuracy — all in one separate commit.

Two commits total; ~1 dev-day.

## 1. Context & motivation

**Why decompose M1.6.** The original PRD §10 M1.6 was a single milestone spanning 8 tasks across very different domains (CLI subcommands + cross-session analyzer + filesystem watching + 2 new export formats + a consistency test + docs). Several of those need their own design pass — Speedscope/HTML require pivot adaptation (no tokenizer → use duration metric), `aggregate` needs an `AggregateReport` type, `watch` needs concurrency design. Shipping all 8 as one milestone would have meant either (a) skipping design rigor and accepting drift, or (b) writing 8 specs back-to-back with no incremental delivery.

**Why M1.6.1 = list + polish.** `list` is the smallest, clearest, most independent piece — pure CLI discovery + table rendering, no shared types changes, no pivot impact. Bundling it with the M1.5 audit follow-ups gives one well-scoped 1-day milestone: ship a small new feature + clear out the 8 known minor debts before adding new architectural surface.

**Why drop `export`.** The original spec — `cmd/export.rs::Args { session: String, format, out }` — is byte-for-byte equivalent to existing `agentprof analyze --session X --export md --output Y`. The only conceptual difference was "export explicitly rejects `--format tui`" but `analyze --export tui` already fails-fast on non-tty. Keeping `export` would create two CLI doors to the same function — confusing rather than clarifying.

## 4. Architecture & data flow

```
agentprof list --since 7d --limit 20
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│ cmd::list::run                                           │
│ 1. CopilotAdapter::discover_sessions(root)               │
│    → Vec<SessionRef>  (cheap dir scan, no jsonl parse)   │
│ 2. filter by `mtime >= now - since`                      │
│ 3. truncate to `--limit N`                               │
│ 4. for each: load_session → derive_episodes → analyze    │
│    → Vec<Result<ListRow, (SessionRef, anyhow::Error)>>   │
│ 5. format_table(rows) → String                           │
│ 6. write to stdout                                       │
│ 7. if any failures: stderr summary line                  │
└─────────────────────────────────────────────────────────┘
```

`ListRow` is a private struct in `cmd/list.rs`:

```rust
struct ListRow {
    id: String,
    started_at: DateTime<Utc>,
    model: Option<String>,
    turns: usize,
    out_tokens: u64,
    duration: Option<Duration>,
    size_bytes: u64,
}
```

Constructed from `(SessionRef, AnalysisReport)` — no cross-cutting changes to existing core types.

## 5. `list` subcommand spec

### 5.1 CLI shape

```
agentprof list [OPTIONS]

OPTIONS:
  --agent <AGENT>      Agent whose sessions to list. [default: copilot]
  --root <PATH>        Override default session-state root.
  --since <DURATION>   Show sessions modified within this duration. [default: 7d]
                       Format: <N>d / <N>h / <N>m / <N>s / "all"
  --limit <N>          Maximum sessions to show. [default: 20] (0 = unlimited)
  -h, --help           Print help.
```

`--agent` accepts the same `AgentKind` enum as `analyze`; only `copilot` is currently implemented (others return `UserError` per existing pattern).

### 5.2 Discovery + parse pipeline

1. Resolve root: `--root` arg > `adapter.default_session_root()` > `UserError`.
2. `adapter.discover_sessions(&root)` — returns `Vec<SessionRef>` already sorted by mtime descending.
3. **Filter**: `since_secs` parsed from `--since`. Keep `s` where `(SystemTime::now() - s.modified_at) <= Duration::seconds(since_secs)`. `"all"` disables the filter.
4. **Truncate**: `.into_iter().take(limit).collect()` (0 = no truncate).
5. **Per-session analyze**: synchronously load + derive + analyze each, collecting `Vec<Result<ListRow, (SessionRef, anyhow::Error)>>`. Failures are caught but logged for the summary line.
6. Render the successful rows; print the failure count to stderr if non-zero.

### 5.3 Column rendering

7 columns, manual padding, plain-text output:

| Column | Source | Format |
|---|---|---|
| `ID` | `SessionRef.id` | 36-char UUID (full, not truncated) |
| `Started` | `meta.started_at` | `YYYY-MM-DD HH:MM UTC` (no seconds) |
| `Model` | first `TurnSummaryRow.model` | `Option<String>` → `-` if None |
| `Turns` | `report.turn_summary.len()` | `usize` |
| `Out-tokens` | sum of `TurnSummaryRow.output_tokens` | compact (`1.2k`, `2.45M`, `12`) |
| `Duration` | `last.started_at - first.started_at` from turn_summary; fallback `-` if no turns | reuses `views::format::human_short` |
| `Size` | `SessionRef.size_bytes` | binary (`850k`, `42.4M`) |

Header row in bold via ANSI escape (`\x1b[1m...\x1b[0m`) only when stdout is a TTY (use `IsTerminal` check). Piped output stays plain.

Column widths: precomputed from header lengths + max row content lengths. Single pass; no line wrapping; long fields get a single trailing space separator. The Out-tokens / Size columns use compact base-2/SI formatting (write a small helper or hand-format the 3 buckets — sub-1k → integer; 1k–1M → `<N.N>k`; ≥1M → `<N.NN>M`).

Footer line written to stdout after the table (separate paragraph):

```
(20 of 47 sessions shown; --since=7d --limit=20)
```

If filter exhausts everything: `(no sessions matching --since=7d in <root>)`. Exit 0.

### 5.4 Error handling

- **No root**: `UserError` (1).
- **Root doesn't exist**: `UserError` (1).
- **Empty match**: exit 0 with "(no sessions matching...)" — not an error.
- **Per-session parse failure**: `Err((sref, e))` collected. Successful rows still printed. Stderr summary after the table:
  ```
  3 sessions failed to parse (use `agentprof analyze --session <id>` for details):
    - abc12345-..., def67890-..., ghi54321-...
  ```
  Exit 0 (the command succeeded overall, even if some sessions skipped).
- **All sessions failed**: exit 2 (`DataError`) with stderr message; no table.

### 5.5 Duration parser

Inline helper:

```rust
fn parse_since(s: &str) -> Result<Duration, String> {
    match s {
        "all" => Ok(Duration::MAX),
        s if s.ends_with('s') => parse_n(s).map(Duration::from_secs),
        s if s.ends_with('m') => parse_n(s).map(|n| Duration::from_secs(n * 60)),
        s if s.ends_with('h') => parse_n(s).map(|n| Duration::from_secs(n * 3600)),
        s if s.ends_with('d') => parse_n(s).map(|n| Duration::from_secs(n * 86400)),
        _ => Err(format!("unrecognized --since: {s}; use <N>d/h/m/s or 'all'")),
    }
}
fn parse_n(s: &str) -> Result<u64, String> { s[..s.len()-1].parse().map_err(|e: ParseIntError| e.to_string()) }
```

Note: `std::time::Duration::MAX` for `"all"` — comparison `elapsed <= MAX` always true.

## 10. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| `--since 7d` default surprises user who has all their sessions outside that window | Low | Footer says "0 of N sessions shown; --since=7d --limit=20" — guides them to `--since all` |
| Full analyze on N sessions takes too long | Low | `--limit 20` default + measured 50-session test should stay under 5s; if user complains, M1.6.x can add `rayon` parallelization |
| Compact formatter rounds confusingly (e.g. `999` → `"999"` vs `1023` → `"1.0k"`) | Low | Edge cases unit-tested; downstream piped consumers can use `analyze --export json` for raw counts |
| Polish #7 fixture edit breaks existing fixture-based tests in other crates | Low | `with-skill-invoked` is only consumed by `agentprof-tui/tests/views.rs` snapshot; quick `cargo test` post-edit confirms |
| Polish #4 warn-on-ignored-flag interferes with scripts that pass `--output` blindly | Negligible | It's a warning to stderr, not an error; scripts unaffected. If real users hit it, future work can introduce `--export json --output X` rejection |
