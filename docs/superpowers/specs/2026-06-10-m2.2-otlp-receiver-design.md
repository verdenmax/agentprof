> **TL;DR** — A standalone `agentprof ingest-otlp` subcommand that runs

> OTel-emitting agent's) telemetry into the M2.1 SQLite store. Four
> brainstorming decisions settled (all toward maximal coverage):
>
> 1. **Scope** — Full receive → persist MVP (option B). Receive OTLP,

> `upsert_report` + M2.1.1 `upsert_episodes`. ~58h ≈ 7-8 working days,

## 1. The problem

`cmd::list` / `aggregate` / `mcp-waste` / `analyze` all rely on the
adapter discovering session files post-hoc (`events.jsonl` on disk
after Claude Code / Copilot CLI / Codex CLI has flushed them). This
has three structural limits:

1. **Latency** — A live debugging loop can't see in-progress sessions
   until the agent process exits or rolls its log file.
2. **Data loss** — Claude Code (per ADR-0001) prunes its `~/.claude/`
   jsonl on its own schedule. Sessions older than the agent's
   retention window are gone unless agentprof has its own persistence
   (M2.1 helps — but you have to remember to ingest).
3. **Future agents** — Codex CLI, OpenAI-compatible proxies, etc. may
   not have a "log file on disk" surface at all; their only signal
   might be OTLP.

OTLP receiver mode flips the data flow: agentprof becomes the
canonical source-of-truth that agents push to, instead of scraping
their files. ADR-0018's `SessionDataSource` trait was designed
"OTLP-ready", but on closer look the trait fits the **pull/read** side
(list / aggregate consume it). OTLP is **push/write** — it should land
in the storage layer directly via `upsert_report` / `upsert_episodes`,
same path `cmd::analyze` write-through uses. The receiver is a *peer*
of `cmd::analyze` from the perspective of the storage layer, not a
new trait implementor (see §3.1).

### 1.1 What Claude Code actually emits (audit, 2026-06-09)

Claude Code's OpenTelemetry instrumentation (as of v2.x) emits a mix
of signals:

| Signal type | Examples | Frequency |
|---|---|---|
| **Logs** (events) | `claude_code.user_prompt`, `claude_code.tool_decision`, `claude_code.tool_result`, `claude_code.api_request`, `claude_code.api_error`, `claude_code.session.start`, `claude_code.session.end` | per-event |
| **Metrics** (counters) | `claude_code.token.usage` (per model, per direction), `claude_code.session.count`, `claude_code.tool.invocation_count` | aggregated bucket flushes |
| **Traces** | None today (no span emission in current Claude Code) | — |

So M2.2's MVP must handle logs + metrics for Claude Code today;
traces support is preventative for future agents (Codex CLI's
forthcoming OTel support; OpenAI Agents SDK does emit traces).

add a crate dependency edge for no isolation benefit (since the OTLP
code is feature-gated, it's already opt-in compile-wise).

brainstorming may need OTLP + custom proxies + other receiver types
together. **If** that lands, hoist `storage::otlp` into a new
`agentprof-receivers` crate at that point as additive refactor. YAGNI
for v0.2.x.

### 2.3 OTLP receiver vs `SessionDataSource` trait

ADR-0018 framed OTLP as "future 4th implementor of `SessionDataSource`".
Re-examined during M2.2 brainstorm: `SessionDataSource` is the
**read-side** abstraction (`discover` / `load_session` /
`load_episodes`), consumed by `cmd::list` / `aggregate` / `mcp-waste`.
OTLP is a **write-side** flow — receive, decode, persist. There's no
natural `discover()` for OTLP (sessions arrive asynchronously) and no
`load_session()` (already persisted via upsert).

**Decision**: OTLP receiver does NOT implement `SessionDataSource`.
It writes to storage via existing helpers; downstream readers (list /
aggregate / etc.) see the OTLP-ingested sessions through the existing
`SqliteDataSource` impl. No trait or downstream changes needed.

Update ADR-0018 with a footnote in T-final clarifying this.

### 3.2 `TypedEvent` enum (storage::otlp::typed)

OTLP wire types (`LogRecord` / `Metric` / `Span`) are heterogeneous and
verbose. Convert at the boundary to a uniform internal enum:

```rust
#[derive(Debug, Clone)]
#[non_exhaustive]
pub enum TypedEvent {
    /// `claude_code.session.start` log → opens a SessionBuffer.
    SessionStart {
        session_id: String,
        agent: AgentKind,
        started_at: DateTime<Utc>,
        model: Option<String>,
        cwd: Option<PathBuf>,
    },
    /// `claude_code.user_prompt` log → goes into Episodes.turns[*].
    UserPrompt {
        session_id: String,
        turn_id: String,
        timestamp: DateTime<Utc>,
        prompt_size_bytes: Option<u64>,
    },
    /// `claude_code.tool_decision` log → opens a ToolCall in Episodes.tools.
    ToolDecisionStart {
        session_id: String,
        turn_id: Option<String>,
        tool_name: String,
        source: ToolSource,
        timestamp: DateTime<Utc>,
        user_approved: bool,
    },
    /// `claude_code.tool_result` log → closes a ToolCall.
    ToolResult {
        session_id: String,
        turn_id: Option<String>,
        tool_name: String,
        timestamp: DateTime<Utc>,
        status: ToolCallStatus,
    },
    /// `claude_code.token.usage` metric data point → goes into model_metrics.
    TokenUsage {
        session_id: String,
        model: String,
        direction: TokenDirection,  // Input / Output / CacheRead / CacheCreation
        value: u64,
        timestamp: DateTime<Utc>,
    },
    /// `claude_code.session.end` log → flushes buffer.
    SessionEnd {
        session_id: String,
        ended_at: DateTime<Utc>,
    },
    /// Catch-all for unrecognized signal — drop with tracing::debug.
    Unrecognized {
        signal: SignalKind,
        identity: String,
    },
}

#[derive(Debug, Clone, Copy)]
#[non_exhaustive]
pub enum SignalKind { Log, Metric, Trace }

#[derive(Debug, Clone, Copy)]
#[non_exhaustive]
pub enum TokenDirection { Input, Output, CacheRead, CacheCreation }
```

Future agents (Codex / OpenAI proxies) add variants here — `#[non_exhaustive]` keeps it future-proof.

### 3.3 `SessionBuffer` (storage::otlp::session_router)

```rust
struct SessionBuffer {
    session_id: String,

    started_at: DateTime<Utc>,

        // Periodically (every 30s) scans buffers, flushes any with
```

## 4. CLI surface

### 4.1 New subcommand: `agentprof ingest-otlp`

```
agentprof ingest-otlp [OPTIONS]

Run an OTLP receiver, persisting telemetry into the SQLite store.

OPTIONS:
  --listen-grpc <ADDR>          gRPC listen socket addr. Default 127.0.0.1:4317.
                                Use "" or omit + --no-grpc to disable.
  --listen-http <ADDR>          HTTP/protobuf listen addr. Default 127.0.0.1:4318.
                                Use "" or omit + --no-http to disable.
  --no-grpc                     Disable gRPC listener entirely.
  --no-http                     Disable HTTP listener entirely.
  --listen-token <TOKEN>        Require Authorization: Bearer <TOKEN> on every
                                request. Default: no auth.
  --tls-cert <PATH>             Enable TLS using this server certificate (PEM).
                                Both listeners served over TLS.
  --tls-key <PATH>              Server private key (PEM). Required with --tls-cert.
  --tls-client-ca <PATH>        Require + verify client certificate signed by
                                this CA (mTLS). Implies TLS.
  --session-idle-timeout <DUR>  Per-session idle flush threshold. Default 5m.
                                Accepts humantime: 30s, 2m, 1h.
  --shutdown-grace <DUR>        SIGINT/SIGTERM graceful shutdown deadline.
                                Default 10s.
  --storage-path <PATH>         Override DB path (global). Default per [storage].
  --quiet                       Suppress per-event tracing output (global).

EXIT CODES:
  0  graceful shutdown after SIGINT / SIGTERM, all sessions flushed
  1  user error (bad CLI flags, invalid TLS files, both transports disabled)
  2  data error (DB open failed, migration failed)
  3  bind failed on a non-disabled listener address
```

Refuse to start when:
- Both `--no-grpc` AND `--no-http` are set (no listener = pointless)
- `--tls-cert` without `--tls-key` or vice versa
- `--tls-client-ca` set but no `--tls-cert`
- `--listen-grpc` address invalid (clap-level reject)

### 4.2 Wire-protocol contract

- gRPC: bind on `--listen-grpc` addr; serve `opentelemetry.proto.collector.{logs,metrics,trace}.v1.{Logs,Metrics,Trace}Service`. Each service responds `ExportXxxResponse { partial_success: None }` on success (full ack), `tonic::Status::internal("...")` on processing error, `tonic::Status::unauthenticated("...")` on bearer mismatch.
- HTTP/protobuf: bind on `--listen-http` addr; routes `POST /v1/{logs,metrics,traces}` with `Content-Type: application/x-protobuf`. Body decoded as same proto types as gRPC. Returns 200 + empty `ExportXxxResponse` on success; 401 on auth fail; 415 on wrong Content-Type; 5xx on processing error.

### 4.3 Existing CLI commands unaffected

`analyze` / `list` / `aggregate` / `mcp-waste` / `db ingest` /
`watch` / etc. all unchanged. OTLP-ingested sessions appear identical
to JSONL-ingested ones (both end up in `sessions` table via
`upsert_report`); downstream `cmd::list` etc. just see more rows.

## 5. Pipeline detail

### 5.1 Decode → ingest

```
[wire: tonic Request / axum Request<Bytes>]
   │
   ▼ decode_proto (decoders use same opentelemetry-otlp proto types)
ExportLogsServiceRequest / ExportMetricsServiceRequest / ExportTraceServiceRequest
   │
   ▼ pipeline::ingest_logs(request, router) / ingest_metrics / ingest_traces
flatten ResourceLogs / ResourceMetrics / ResourceSpans → iter of (resource_attrs, payload)
   │
   ▼ mapper::map_log_record(payload, resource_attrs) -> Vec<TypedEvent>
   │   mapper::map_metric(payload, resource_attrs) -> Vec<TypedEvent>
   │   mapper::map_span(payload, resource_attrs) -> Vec<TypedEvent>
Vec<TypedEvent>
   │
   ▼ for each event: router.ingest(event)
SessionRouter routes by event.session_id() into the right SessionBuffer
   │
   ▼ on SessionEnd OR idle OR OOM cap: router.flush_session(id)
SessionBuffer::into_persistable() → (AnalysisReport, Episodes)
   │
   ▼ storage::upsert_report + storage::upsert_episodes
SQLite row written. Session id propagates to read paths via SqliteDataSource.
```

### 5.2 Session derivation

Resource attribute `session.id` is the source of truth (OTel
canonical, used by Claude Code's instrumentation). Fallback chain:

1. `resource.attributes["session.id"]` — preferred
2. `resource.attributes["claude.session_id"]` — Claude Code alias
3. `log_record.attributes["session.id"]` — per-event escape hatch
4. (none) → drop event with `tracing::warn!(name = %event_name, "no session.id; dropping")`

Agent detection (similar fallback):

1. `resource.attributes["service.name"]` — `"claude-code"`, `"codex-cli"`, etc.
2. `resource.attributes["agent.kind"]` — agentprof convention if we
   evangelize a `service.name = "claude-code"` upstream
3. (none) → default `AgentKind::Copilot` + `tracing::warn`

### 5.3 Buffer flush triggers (priority order)

1. **Explicit**: `SessionEnd` event for that session_id → flush immediately
2. **OOM cap**: `bytes_estimate > 16 MB` OR `events.len() > 100k` → flush immediately (and tracing::warn that the session is large)
3. **Idle**: `last_seen + config.session_idle_timeout < now` → flush (background sweeper task)
4. **Shutdown**: SIGINT / SIGTERM → flush all buffers, exit 0 within `shutdown_grace`

### 5.4 `SessionBuffer::into_persistable()` algorithm

Convert the `Vec<TypedEvent>` accumulated for one session into the
two persistent shapes:

```
AnalysisReport
   - meta: SessionMeta {
        id, agent, started_at (from SessionStart),
        // raw_path: synthesized as "otlp://{session_id}"
     }
   - tool_rank: rolled up from ToolDecisionStart + ToolResult events
   - turn_summary: rolled up from UserPrompt events
   - model_metrics: rolled up from TokenUsage events (by model)
   - loaded_mcp_tools: empty (Claude Code doesn't emit this via OTLP today)

Episodes
   - turns: built from UserPrompt + ToolResult pairings
   - tools: BTreeMap from (tool_name) → ToolEpisode {
        calls: Vec<ToolCall> built from ToolDecisionStart → ToolResult pairs
     }
   - hooks: empty (Claude Code doesn't expose hooks via OTLP)
   - skills: empty (same)
   - mode_segments: empty
   - aborts: from `claude_code.api_error` events (future enhancement)
   - warnings: any MapperError encountered during pairing
```

**Pairing algorithm** for tool calls: hold a stack of `ToolDecisionStart`
events keyed by `(session_id, tool_name, turn_id)`; pop matching
`ToolResult` events into completed `ToolCall` structs. Orphaned starts
(no matching result) at flush time become `ToolCall { status:
ToolCallStatus::Unknown }` + a `DeriveWarning`.

### 5.5 Soft-fail semantics

OTLP receiver is a **streaming** consumer; one bad event can't kill
the whole session, let alone the whole server.

| Failure | Behavior |
|---|---|
| Single event decode error | `tracing::warn!`, drop event, ack OTLP request |
| Session start without session.id | Drop event, ack request |
| Buffer OOM | Force-flush partial session, log warning |
| Single session flush fails (e.g. DB write error) | `tracing::error!`, drop buffer, continue serving other sessions |
| Whole DB unreachable | First flush attempt fails → all subsequent flushes also fail; receiver continues accepting requests but logs every flush failure. Operator must restart or fix DB. |
| TLS handshake failure | Single connection rejected, server continues |
| Bearer mismatch | Request 401, server continues |

## 8. ADR (deferred to T-final)

**ADR-0021 — OTLP receiver architecture**

- Status: Accepted (2026-06-10)
- Context: real-time alternative to jsonl scraping; ADR-0001 events-first
  posture inverted (write-side push instead of read-side scrape)
- Decided: standalone `ingest-otlp` subcommand; `storage::otlp` submodule
  (NOT new crate, NOT new trait impl); gRPC + HTTP/protobuf; logs +
  metrics + traces; bearer + optional mTLS auth
- Considered: subscription bridge (rejected — pub/sub not needed for v0.2);
  embedding in `watch` mode (rejected — different lifecycle); separate
  receiver crate (deferred to Phase 3 when more receivers land)
- Codified: OTLP receiver does NOT implement `SessionDataSource`
  (ADR-0018 footnote)
- Consequences: storage gains its first real network surface;
  v0.2.x dogfood requires opt-in `cargo install --features otlp` or
  shipping a separate "ingest-otlp-enabled" binary
