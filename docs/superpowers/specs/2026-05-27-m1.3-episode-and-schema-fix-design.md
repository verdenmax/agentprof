# M1.3 Episode derivation + Copilot schema calibration — design

> 📝 **Post-implementation note (2026-06-08, v0.1.1):** The
> `ParseWarning::MissingField` variant referenced in §6 (Stage 5 task
> list, line ~460) describes a **planned** variant that was superseded
> during M1.3 implementation. The actual shipped enum lives in
> `crates/agentprof-core/src/error.rs`; the audit-driven struct-Optional
> fixes happened, but they were filed under different `ParseWarning`
> variants (`Json` carrying line-level `error: String`, and the
> `Unclosed*` family). Tracked in the session-store `plan_drift` table
> under id `parsewarning-variants`.

## 1. One-liner

**M1.3 = "events-first 数据层完工"**：先用 `cargo xtask schema-audit` 把 M1.2 落地后真实数据暴露的 schema 缺口（69 个 `Unknown` 事件、`HookStart=1 vs HookEnd=210` 等不平衡）量化清楚，落地为 `CopilotEvent` 新变体；然后在 `agentprof-core` 里实现 `derive_episodes` 纯函数，把扁平事件流聚合为 5 种共享 Episode 类型（`Turn` / `ToolEpisode` / `HookEpisode` / `SkillEpisode` / `ModeSegment`），为 M1.4 CLI / M1.5 TUI 提供干净的分析输入。

## 2. Context / why now

M1.2 CopilotAdapter 已合并到 `main`（commit `45f6861`）。M1.2 收尾时跑了一次真实 Copilot CLI 数据的 demo：

| 指标 | 数值 | 含义 |
|---|---|---|
| `CopilotEvent::Unknown` 事件 | 69（当前 session 1796 事件中）| 真实 Copilot CLI 1.0.54 至少有 1-2 种事件类型 M1.2 的 18 个 named variant 没覆盖 |
| `ParseWarning` 总数 | 1325 / 1796（73%）| 大概率包含 `OutOfOrder` 噪声 + 真实 schema 缺陷 |
| `HookStart=1` vs `HookEnd=210` | 极度不平衡 | 强烈暗示 `hook.start` 的真实 `type` 字符串与我们 clean-room 推导的不一致 |
| `ToolExecStart=755` vs `ToolExecComplete=209` | 不平衡 | 同上 |

这些是 M1.2 设计阶段无法预见的——只有在跑过真实数据后才知道。M1.3 在着手 `derive_episodes` 之前必须先把 schema 校准好，否则 Episode 配对算法会被错误前提毒化。

同时，M1.2 design spec（`2026-05-26-copilot-adapter-event-first-design.md`）已经预先定义了 `agentprof-core::episode/` 与 `agentprof-core::analyzer/` 两个模块。M1.3 落地 `episode/`；`analyzer/` 推到 M1.4。

## 3. Goals & Non-Goals

### 3.1 Goals

- **G1**：xtask schema-audit 子命令长期可用，每次 Copilot CLI 升级都能重跑校准
- **G2**：当前 Copilot CLI 1.0.54 数据上的 `Unknown` 事件率降到 0
- **G3**：`hook.*` / `tool.*` 等关键事件对配对率接近 100%（不平衡差 ≤ 5%）
- **G4**：`agentprof-core::episode` 模块 ship，含 5 种 Episode 类型 + `Episodes` 容器 + `DeriveWarning`
- **G5**：`derive_episodes` 在 9 个 M1.2 fixture + 至少 1 个新孤儿 fixture 上有 insta snapshot
- **G6**：`derive_episodes` 是纯函数、单遍 O(N_events)、总是产出 Episodes（不抛错）
- **G7**：所有公开 API 带 rustdoc + `# Examples`；所有 gates（fmt / clippy `-D warnings` / test / rustdoc `-Dwarnings`）全绿
- **G8**：L1/L2/L3 文档同 PR 同步（ADR-0002 标 Updated，新增 ADR-0004，L1 architecture.md §6 落地 Episode）

### 3.2 Non-Goals（M1.3 显式不做）

- ❌ Analyzer rollups (`tool_rank` / `hook_rank` / `skill_rank` / `turn_summary` / `aggregate`) → M1.4
- ❌ CLI 子命令 / 用户可见的命令行入口 → M1.4
- ❌ TUI / 任何 UI 呈现 → M1.5
- ❌ 任何导出格式（md / csv / json / speedscope / html）→ M1.4-M1.6
- ❌ Token rollups / tokenizer 集成（ADR-0001 已延后 Phase 2）
- ❌ SQLite 持久化 / OTLP 接收（Phase 2）
- ❌ Claude / Codex 适配（Phase 2 / 3）
- ❌ schema-audit 自动生成 Rust 变体代码（人眼审一遍更安全）
- ❌ 在 schema-audit 报告里上传任何遥测（100% 本地）

## 5. Architecture

### 5.1 Phase 流（严格依序）

```
Phase A: 校准                     Phase B: schema 修正           Phase C: episode 聚合
┌─────────────────────┐         ┌──────────────────────┐       ┌────────────────────┐
│ cargo xtask         │  ──→    │ 扩 CopilotEvent      │  ──→  │ derive_episodes    │
│   schema-audit      │         │ + ParseWarning 变体  │       │ (lenient + warns)  │
│                     │         │ + 更新 ADR-0002      │       │                    │
│ 输出 Unknown 分类、 │         │ + 添加变体 round-trip │       │ 5 种 Episode：     │
│ Warning 分布、      │         │   测试 + 1 个 fixture │       │  Turn / Tool /     │
│ 候选变体名          │         │   覆盖新变体          │       │  Hook / Skill /    │
└─────────────────────┘         └──────────────────────┘       │  ModeSegment       │
                                                                │ + DeriveWarning    │
                                                                └────────────────────┘
```

**为什么严格依序而非并行**：如果 derive_episodes 基于错误的 schema 假设设计（例如假定 `HookStart` 真的有 1 个，而真实数据有 210 个但被错命名），算法会过度复杂化处理"不存在的不平衡"。Phase A 报告先于 Phase C 实现是必要的。

## 6. Data Model

### 6.1 Episode 类型（agentprof-core::episode）

```rust
// turn.rs
#[non_exhaustive]
pub struct Turn {
    pub id: String,
    pub started_at: DateTime<Utc>,
    pub ended_at: Option<DateTime<Utc>>,
    pub model: Option<String>,
    pub mode: Option<Mode>,
    pub output_tokens: Option<u32>,
    pub status: TurnStatus,
    pub tool_calls: Vec<usize>,     // indices into Episodes.tools[name].calls
    pub hook_calls: Vec<usize>,
    pub skill_calls: Vec<usize>,
}

#[non_exhaustive]
pub enum TurnStatus {
    Open,                              // 没看到对应 turn_end
    Completed,
    Aborted(AbortInfo),
}

#[non_exhaustive]
pub struct Span {
    pub started_at: DateTime<Utc>,
    pub ended_at: DateTime<Utc>,       // 孤儿合成时 = started_at
}

// tool.rs
#[non_exhaustive]
pub struct ToolEpisode {
    pub name: String,
    pub source: ToolSource,            // M1.2 已有，agentprof_core::model::ToolSource
    pub calls: Vec<ToolCall>,
    pub total_duration: Duration,
    pub fail_count: u32,
}

#[non_exhaustive]
pub struct ToolCall {
    pub span: Span,
    pub turn_id: Option<String>,
    pub status: ToolCallStatus,
    pub user_requested: bool,
}

#[non_exhaustive]
pub enum ToolCallStatus {
    Success,
    Failure { message: Option<String> },
    OrphanSynthesizedStart,            // ★ 没看到 Start（HookEnd/Complete 先到），合成了占位 Start
    OpenAtEndOfSession,                // ★ 看到 Start 但 session 结束前没 End；span.ended_at = last_event_ts
}

// hook.rs
#[non_exhaustive]
pub struct HookEpisode {
    pub name: String,
    pub calls: Vec<HookCall>,
    pub total_duration: Duration,
    pub failure_count: u32,
}

#[non_exhaustive]
pub struct HookCall {
    pub span: Span,
    pub turn_id: Option<String>,
    pub success: bool,
    pub synthesized_start: bool,       // ★ flag
}

// skill.rs
#[non_exhaustive]
pub struct SkillEpisode {
    pub name: String,
    pub invocations: Vec<SkillInvocation>,
    pub subsequent_tool_calls: u32,
}

#[non_exhaustive]
pub struct SkillInvocation {
    pub at: DateTime<Utc>,
    pub turn_id: Option<String>,
    pub triggered_tools: Vec<usize>,   // 该 invocation 后续窗口内的 ToolCall 索引
}

// mode_segment.rs
#[non_exhaustive]
pub struct ModeSegment {
    pub mode: Mode,
    pub started_at: DateTime<Utc>,
    pub ended_at: Option<DateTime<Utc>>,
}

#[non_exhaustive]
pub enum Mode {
    Ask,
    Auto,
    Expert,
    Unknown(String),                   // 兜底未知 mode
}

// episodes.rs
#[non_exhaustive]
pub struct Episodes {
    pub turns: Vec<Turn>,
    pub tools: BTreeMap<String, ToolEpisode>,
    pub hooks: BTreeMap<String, HookEpisode>,
    pub skills: BTreeMap<String, SkillEpisode>,
    pub mode_segments: Vec<ModeSegment>,
    pub aborts: Vec<AbortInfo>,
    pub warnings: Vec<DeriveWarning>,
}

// warning.rs
#[non_exhaustive]
pub enum DeriveWarning {
    SynthesizedStart {                 // 配对：见到孤儿 End（HookEnd / ToolExecComplete），算法合成了 0ms Start
        kind: EventKind,
        end_event_id: String,
    },
    OpenAtEndOfSession {               // 配对：见到 Start 但 session 在 End 之前结束
        kind: EventKind,
        start_event_id: String,
    },
    AbortWithoutOpenElement {          // Abort 触发时没有任何开着的 Turn / Tool / Hook
        reason: String,
        at: DateTime<Utc>,
    },
    NonMonotonicTimestamp {            // ev.timestamp() < prev_ts
        event_id: String,
        prev_at: DateTime<Utc>,
        this_at: DateTime<Utc>,
    },
}

#[non_exhaustive]
pub struct AbortInfo {
    pub reason: String,
    pub at: DateTime<Utc>,
}
```

## 7. Algorithms

### 7.1 derive_episodes 状态机

```text
INPUT:  events: &[E: Event], meta: &SessionMeta
OUTPUT: Episodes（含 warnings）

state := DeriveState::default()
       turns: Vec<Turn>
       open_turn_idx: Option<usize>
       open_tool_calls: Vec<(name, ToolCall_in_progress)>   ← 栈
       open_hook_calls: Vec<(name, HookCall_in_progress)>
       open_skills: Vec<(name, SkillInvocation_partial, event_window_remaining)>
       current_mode_segment: ModeSegment
       prev_ts: Option<DateTime<Utc>>
       aborts: Vec<AbortInfo>
       warnings: Vec<DeriveWarning>

for ev in events:
    if let Some(prev) = state.prev_ts:
        if ev.timestamp() < prev:
            warn(NonMonotonicTimestamp { ... })
    state.prev_ts = Some(ev.timestamp())

    match ev.kind():
        TurnStart        → push new Turn { id, status: Open, ... } to turns; open_turn_idx = last
        TurnEnd          → close turns[open_turn_idx] if Some; 否则 synthesize 0-duration Turn + warn(SynthesizedStart{kind: TurnStart, end_event_id: ev.id()})
        ToolExecStart    → push (name, ToolCall{ span.start = ts, ... }) onto open_tool_calls
        ToolExecComplete → pop最近匹配 (name) 的 open_tool_calls；不匹配则 synthesize Start，warn(SynthesizedStart)
                           然后 close 这个 ToolCall（写 span.end, status, etc.）
                           append 到 tools[name].calls, 同时 turn.tool_calls.push(idx)
        HookStart        → push (name, HookCall) onto open_hook_calls
        HookEnd          → 同 ToolExecComplete 对偶逻辑
        SkillInvoked     → push (name, SkillInvocation{..}, K events to track) onto open_skills
        ModeChanged      → close current_mode_segment (ended_at = ts), 开新一段
        Abort            → 找 open_turn / open_tool_calls / open_hook_calls 中最近开的（按 timestamp）
                           attach AbortInfo 到该元素
                           都为空则 aborts.push(AbortInfo) + warn(AbortWithoutOpenElement)
        Unknown          → 静默忽略（Phase B 已修 schema，这里残留只是 forward compat）
        其他 EventKind   → 影响 meta 但不影响 episodes（如 SystemMessage / SessionInfo / Shutdown）

    // skill 触发跟踪：所有 open_skills 的 window_remaining -= 1
    if ev.kind() == ToolExecStart:
        for skill in open_skills:
            skill.triggered_tools.push(idx_of_this_tool_call)

end-of-loop:
    所有未闭合的 Turn → status remains Open, ended_at = None
    所有未闭合的 ToolCall/HookCall → span.ended_at = last_ev_ts（或保持 Open，待 §7.2 决定）

return Episodes { turns, tools, hooks, skills, mode_segments, aborts, warnings }
```

### 7.2 边界情况决策

| 情况 | 处理 | 理由 |
|---|---|---|
| Turn 没结束（实时 session）| `status = Open`, `ended_at = None` | 实时 session 这是正常的，不发 warning |
| ToolCall / HookCall 看到 Start 但没 End | `span.ended_at = last_event_ts`，`status = OpenAtEndOfSession`；发 `DeriveWarning::OpenAtEndOfSession` | 保持出现过的事件计数完整；UI 可标灰色 |
| HookEnd / ToolExecComplete 没匹配 Start | 合成 Start at `ended_at`（0ms span），`status = OrphanSynthesizedStart`；发 `DeriveWarning::SynthesizedStart`；`HookCall.synthesized_start = true` | 保持计数完整；UI 可标"前面有未捕获事件" |
| Mode 没看到任何 ModelChange 或 ModeChanged | 初始一段 `Mode::Unknown("default".into())`，从 session.start 时间开到 session 结束 | 永远有至少一段 ModeSegment |
| 多个 Abort 命中同一个 open Turn | 最早的 Abort wins，其余 push 到 `Episodes.aborts`（unattached）+ 不再 warn（已记录）| 简单确定性 |
| Abort 触发时所有可 attach 元素都已 closed | `Episodes.aborts.push(AbortInfo)` + 发 `DeriveWarning::AbortWithoutOpenElement` | 不丢数据；UI 可在 session-level 时间线标记 |
| 时间戳非单调（`ev.ts < prev_ts`）| 仍照样处理事件（顺序不变），但发 `DeriveWarning::NonMonotonicTimestamp` | 数据来自 async 写入，不重排避免引入更大不一致 |

### 7.3 复杂度

| 操作 | 时间 | 空间 |
|---|---|---|
| `derive_episodes(events, meta)` | O(N_events × log K) where K = max concurrent open tool/hook stack depth (typically < 10) | O(N_episodes + N_warnings) |
| Full M1.3 pipeline (parse + derive) on 1796 events | < 100ms（估计）| < 10MB |

## 8. Testing Strategy

| 层 | 文件 | 测试内容 |
|---|---|---|
| 单元测试 | `crates/agentprof-core/src/episode/{turn,tool,hook,skill,mode_segment,derive,warning}.rs` 内嵌 `#[cfg(test)]` | 每个数据类型 ctor / `#[non_exhaustive]` 构造路径；derive 单 event 的 step 函数（如有提取，用直接 hand-crafted 的小 event slice 验证，**不依赖 adapter**）|
| 集成测试 | `crates/agentprof-adapters/tests/episode_derive.rs` | 在 M1.2 的 9 个 fixture + 新 `orphan-events/` fixture 上跑 `derive_episodes`，每 fixture → 1 个 insta snapshot `episode__<fixture>.snap`。**放这里而非 `agentprof-core/tests/` 是为了避免 dev-dep 循环**（test 既要 adapter 加载 fixture，又要 core 跑算法；adapter 已经依赖 core，反过来不行）|
| 新 fixture | `crates/agentprof-adapters/tests/fixtures/copilot/orphan-events/` | 故意写 1 个 HookEnd 没 Start、1 个 ToolComplete 没 Start、1 个 Abort 无 open 元素 |
| Round-trip 测试 | `crates/agentprof-adapters/tests/copilot_event_parse.rs` | 每个新增 CopilotEvent variant 加 1 个 case |
| xtask 自身测试 | `xtask/tests/schema_audit.rs` | 给 audit 一个 fixture root（用 `crates/agentprof-adapters/tests/fixtures/copilot/`），断言报告 markdown 含 "## Session 覆盖" / "## Unknown 事件分类" / "## ParseWarning 分布" / "## 事件类型平衡分析" 4 段（不做 snapshot，避免脆性）|

**测试稳定性**：所有时间相关用 fixture 里固定的 ISO-8601 timestamp，绝不用 `Utc::now()`；`Duration` 计算用具体 Span 之间的减法。

**Insta snapshot 管理**：本地 `cargo insta accept`；CI 用 `cargo insta test --check`。

## 11. Risks & Open Questions

| 风险 / 问题 | 影响 | 缓解 |
|---|---|---|
| schema-audit 报告比预期复杂（>5 个新变体 / 多个 ParseWarning bug）| Phase B 工作量爆炸 | Phase A 是 first commit；audit 出来后**可以回到 brainstorming** 决定是否拆 milestone（如 M1.3a/M1.3b）|
| 多版本 Copilot CLI 数据并存 | schema-audit 报告可能给出冲突信号 | xtask 报告含 `agent_version` 分布段；变体设计优先就高版本 |
| `derive_episodes` 算法实测远超 100ms | 后续 TUI 实时刷新有压力 | M1.3 不优化；M1.5 TUI 来评估是否需要 partial derive / 索引化 |
| `triggered_tools` 窗口 K 值不合理 | Skill 关联性失真 | 默认 K=50，留 `derive_episodes_with_config(..., DeriveConfig)` 后门，M1.4 CLI 再暴露 |
| insta snapshot 在多平台漂移（CI macOS/Linux）| snapshot 红 | 序列化用确定性 BTreeMap / Vec；时间用 fixture 固定值；不用 `Utc::now()` |
| ADR-0004 设计在 Phase C 实现时被现实推翻 | 需要回头改 ADR | ADR Stage 2 在 Phase C 之前先 draft，之后可改 Status: Superseded / Updated |
