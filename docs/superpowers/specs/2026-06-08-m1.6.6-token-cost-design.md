> answers "how many *tokens* of my context window were wasted on unused
> tool descriptions?" Two data sources via fallback chain: heuristic

> optional sidecar (`--tool-descriptions <PATH>` — auto-detects file

> `compute_waste` signature changes ONCE to take a builder-pattern
> `WasteComputeContext` struct — future M1.6.7+ additions become
> non-breaking. Estimated ~13h ≈ 1.5 working days; ~25 new tests.

## 1. The problem (pre-scoped)

M1.6.5 answered "which MCP tools were loaded but never called" with
COUNTS. It deliberately stopped short of the "View C" question from
the original brainstorming:

> "Of my context budget, how many tokens are wasted on tool descriptions
> that were never actually invoked?"

This question requires per-tool token-cost data, which is NOT in
`events.jsonl`. ADR-0015 D-5 captured this risk and carved it out as
M1.6.6 to isolate `mcp.json` schema-variation uncertainty from M1.6.5's
shipping path.

### 1.1 Where tool descriptions actually live (MCP protocol reality)

Per the MCP spec (`modelcontextprotocol.io`), tool descriptions come
from the server's `tools/list` JSON-RPC response, e.g.:

```json
{
  "tools": [
    {
      "name": "search_issues",
      "description": "Search GitHub issues by query...",
      "inputSchema": {"type": "object", "properties": {...}}
    }
  ]
}
```

`mcp.json` itself stores ONLY server connection config (the VSCode
flavor: `{ command, args, env }`). It does NOT contain descriptions.
Some self-describing variants list tool NAMES but still not
descriptions. Copilot CLI does not cache `tools/list` responses to
disk.

### 1.2 Maintainer's environment (2026-06-08 audit)

- No `~/.copilot/mcp.json` file present
- No MCP plugins installed (`config.json.installedPlugins` only lists `superpowers` — a Copilot CLI plugin, not an MCP server)
- 0 MCP tool calls in any recorded session

Implication: maintainer cannot dogfood M1.6.6 with real MCP data.
Feature value accrues to users who DO have MCP servers configured.
Heuristic default keeps M1.6.6 useful for everyone (gives a "tokens of
the same order of magnitude as reality" estimate); sidecar path
unlocks precision for power users.

## 2. Brainstorming decisions (recap)

Captured live in session 252068e5 on 2026-06-08 (post-M1.6.5):

| Axis | Choice | Rationale |
|---|---|---|
| Data source | Heuristic + optional sidecar (file or dir auto-detect) | Ships value with zero user config; precision available when user provides sidecar |
| Token scope per tool | Full tool entry serialized JSON (`name` + `description` + `inputSchema` + optional annotations) | Matches what agent actually sees in system prompt tool list — most honest representation of context burden |
| Tokenizer | Auto-infer from `session.meta.model` (`gpt-5*`/`gpt-4o*` → `o200k_base`; else → `cl100k_base`) | Highest accuracy per session; respects multi-model sessions in aggregate |
| Sidecar format | Auto-detect by path type: file → global JSON; dir → per-server JSON files (MCP `tools/list` response shape) | Both formats useful: file = manual / scripted; dir = `curl http://server/tools/list > <server>.json` workflow |
| `compute_waste` signature | One BREAKING change to `(report, &WasteComputeContext)` with builder pattern; future additions non-breaking | Avoids repeated signature breaks on every future enhancement |
| Provenance display | `≈` prefix on heuristic numbers; explicit `TokenProvenance` enum in JSON; footer/banner text in md/html/TUI | User must be able to distinguish "real" tokens from "estimated" tokens at a glance |
| `WasteDataSource::TokenCostUnavailable` (planned in M1.6.5 §5.4) | NOT implemented — replaced by `TokenProvenance` field | Heuristic fallback always succeeds, so `Unavailable` never fires; provenance is more useful |

## 3. Architecture

### 3.1 Per-crate responsibility (incremental over M1.6.5)

```
agentprof-core
  └─ model::waste:
       + WasteReport.total_unused_tokens / total_loaded_tokens / token_provenance / tokenizer  (NEW fields)
       + McpServerWaste.unused_tokens / loaded_tokens                                            (NEW fields)
       + McpToolWaste.description_tokens / token_source                                          (NEW fields)
       + TokenProvenance, TokenSource, TokenizerKind enums                                       (NEW types)
  └─ analyzer::waste:
       + WasteComputeContext (builder)                                                           (NEW struct)
       + compute_waste signature change: (report, &WasteComputeContext)                          (BREAKING)
       + compute_token_cost_for_tool helper                                                      (NEW pure fn)
       + infer_tokenizer helper                                                                  (NEW pure fn)
       + DEFAULT_HEURISTIC_TOKENS const                                                          (NEW)

agentprof-adapters
  └─ copilot::tool_sidecar (NEW module)
       Sidecar + load_sidecar (file/dir auto-detect)

agentprof-tui
  └─ views::mcp_waste:
       + 2nd banner line (Tokenizer + Token source)                                              (rendering update)
       + new "Tokens" column in both server pane + tool pane

agentprof-cli
  └─ cmd::analyze + cmd::aggregate + cmd::mcp_waste:
       + --tokens-per-tool N flag (default 200)
       + --tool-descriptions <PATH> flag
       + Construct WasteComputeContext from flags + load Sidecar before compute_waste
  └─ cmd::format::{md,csv,html}:
       + render new token columns + footer note about provenance
```

**Crate-boundary invariants** (unchanged from M1.6.5):
- `agentprof-core` stays leaf — `compute_waste` is pure; takes pre-built
  `Sidecar` and `tokenizer` references through `WasteComputeContext`.
- `agentprof-adapters::copilot::tool_sidecar` owns Copilot-specific
  sidecar loading. Future adapters provide their own equivalents.
- `agentprof-cli` is the only glue layer.

### 3.2 Data flow (single-session analyze)

```text
session.jsonl
  ↓ adapter load + derive + analyze (existing M1.4 path)
AnalysisReport (with meta.model)
  ↓ extract_loaded_set_from_session (M1.6.5)        → wire_loaded
  ↓ load_mcp_config (M1.6.5, optional)              → config_loaded
  ↓ load_sidecar (M1.6.6, optional)                 → sidecar
  ↓ infer_tokenizer(report.meta.model.as_deref())   → tokenizer
  ↓ build WasteComputeContext via builder
  ↓ compute_waste(&report, &ctx)                    → WasteReport (with token fields)
  ↓ renderer (md/json/html/tui — provenance-aware)
stdout / file / TUI
```

### 3.3 Data flow (aggregate / mcp-waste — multi-session)

Same as M1.6.5 cross-session path, but each per-session `compute_waste`
call passes a `WasteComputeContext` constructed once at startup
(sidecar loaded once, tokenizer chosen per-session per its
`meta.model`). `aggregate_waste` sums the per-session
`total_unused_tokens` straight through without re-tokenizing.

### 4.2 New enums (`#[non_exhaustive]`)

```rust
/// Top-level provenance summary for a WasteReport's token numbers.
pub enum TokenProvenance {
    /// All tools used the heuristic constant.
    Heuristic,
    /// All tools had sidecar-provided entries — every count is exact.
    SidecarExact,
    /// Some tools matched the sidecar, others fell back to heuristic.
    Mixed,
}

/// Per-tool provenance — distinguishes sidecar from heuristic at row granularity.
pub enum TokenSource {
    Heuristic,
    SidecarExact,
}

/// Which tiktoken encoding was used. Auto-inferred from session.meta.model
/// via `infer_tokenizer`; can be overridden in WasteComputeContext.
pub enum TokenizerKind {
    Cl100kBase,
    O200kBase,
}
```

### 4.4 Sidecar types (adapters layer)

```rust
// agentprof_adapters::copilot::tool_sidecar

#[non_exhaustive]
pub struct Sidecar {
    by_full_name: BTreeMap<String, ToolEntry>,  // "mcp__github__search" → entry
}

impl Sidecar {
    pub fn lookup(&self, full_name: &str) -> Option<&ToolEntry>;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
}

#[non_exhaustive]
#[derive(Serialize, Deserialize)]
pub struct ToolEntry {
    pub name: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub description: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none", rename = "inputSchema")]
    pub input_schema: Option<serde_json::Value>,
    // Future MCP-protocol fields land here additively.
}

pub fn load_sidecar(path: &Path) -> Result<Sidecar, SidecarError>;
```

`load_sidecar` algorithm:
- If `path.is_file()` → parse as `Map<server, Vec<ToolEntry>>`, flatten to
  `by_full_name`.
- If `path.is_dir()` → enumerate `*.json` files; each file name (sans
  `.json`) is the server; contents are either `{"tools": [...]}` or
  bare `[...]` of `ToolEntry`s.
- Both formats tolerated; mixed JSON shapes within a dir OK.

## 5. Algorithm

### 5.1 `infer_tokenizer`

```rust
pub fn infer_tokenizer(model: Option<&str>) -> TokenizerKind {
    match model {
        Some(m) if m.starts_with("gpt-5") || m.starts_with("gpt-4o") => TokenizerKind::O200kBase,
        _ => TokenizerKind::Cl100kBase,
    }
}
```

Two-class classifier; deterministic; no I/O. Unit-tested with a table
of `(model, expected)` rows. Unknown / missing model → `cl100k_base`
(safer default — matches Anthropic Claude's token-count
approximation too).

### 5.2 `compute_token_cost_for_tool` (per-tool, pure)

```rust
pub fn compute_token_cost_for_tool(
    tool_name: &str,
    sidecar: Option<&Sidecar>,
    heuristic: u64,
    tokenizer: &CoreBPE,
) -> (u64, TokenSource) {
    if let Some(entry) = sidecar.and_then(|s| s.lookup(tool_name)) {
        let json = serde_json::to_string(entry).unwrap_or_default();
        return (tokenizer.encode_ordinary(&json).len() as u64, TokenSource::SidecarExact);
    }
    (heuristic, TokenSource::Heuristic)
}
```

### 5.3 `compute_waste` updates (M1.6.6 changes)

After M1.6.5's existing logic (sets, server grouping), augment:
- For each `McpToolWaste`: call `compute_token_cost_for_tool`, store
  `description_tokens` + `token_source`.
- Per server: sum `unused_tokens` = Σ `t.description_tokens` for
  `t.call_count == 0`; `loaded_tokens` = Σ all `t.description_tokens`.
- Top-level: sum across servers.
- `token_provenance`: derive from per-tool `token_source` distribution
  (all Heuristic → Heuristic; all SidecarExact → SidecarExact; mixed → Mixed).
- `tokenizer`: store `ctx.tokenizer` verbatim.

Complexity: O(loaded × avg_tool_json_size) per session — sub-millisecond
for typical (< 100 tools).

### 5.4 `aggregate_waste` updates (M1.6.6 changes)

`AggregateWasteReport` gains `total_unused_tokens: u64` field. Per
`McpServerCrossWaste`: `total_unused_tokens: u64` sum across sessions
(note: same server in different sessions may have different tokenizers
or different sidecar coverage; aggregator sums verbatim — caveat
documented in renderer's footer).

## 6. CLI flags (all 3 subcommands)

```
--tokens-per-tool N           Heuristic constant. Default: 200.
                              Ignored for tools whose entry is in the sidecar.

--tool-descriptions <PATH>    Sidecar source.
                              File → global JSON: {"<server>": [<ToolEntry>, ...]}
                              Dir  → per-server: <PATH>/<server>.json containing
                                     either {"tools": [...]} or bare [...]
                              Absent → heuristic-only mode (Provenance::Heuristic).
```

Both flags resolve identically across:
- `agentprof analyze --section mcp-waste ...`
- `agentprof aggregate --by mcp-server ...`
- `agentprof mcp-waste ...`

For `analyze --export tui` (which renders the TUI key-5 view):
- Flags are processed at CLI parse time (before alt-screen entry)
- TUI displays whatever the CLI passed; no in-TUI editing (keeps
  state simple, consistent with M1.6.5 view design)

## 8. Edge cases & error handling

| Case | Behavior |
|---|---|
| Sidecar path absent / `--tool-descriptions` not passed | Heuristic mode; `Provenance::Heuristic`; no error |
| `--tool-descriptions` path doesn't exist | Hard error (user gave explicit path that doesn't resolve) → exit 1 (UserError) |
| Sidecar file is invalid JSON | Hard error → exit 1; tracing::error with parse offset |
| Sidecar file parses but contains no recognized shape | Treat as empty sidecar + tracing::warn; falls back to heuristic |
| Sidecar dir has 0 `*.json` files | Empty sidecar + tracing::warn |
| Sidecar dir has 1 invalid file + 5 valid | Skip invalid (warn), use valid; partial coverage → `TokenProvenance::Mixed` if any tool found |
| Tool in wire/called set but not in sidecar | Heuristic for that tool; `TokenSource::Heuristic`; aggregate-level `TokenProvenance` becomes `Mixed` if any other tool was `SidecarExact` |
| Model in session.meta is unknown / None | Fall back to `cl100k_base` |
| Multi-session aggregate where sessions use different models | Each session uses its inferred tokenizer; aggregator sums verbatim; renderer footer notes "tokenizers may vary across sessions" |
| `--tokens-per-tool 0` | Allowed (rare: user wants to ignore heuristic); zero-out heuristic-derived totals; sidecar-derived numbers remain accurate |
| `--tokens-per-tool` very large (overflow risk) | u64 fits any realistic value; no overflow guard needed |
