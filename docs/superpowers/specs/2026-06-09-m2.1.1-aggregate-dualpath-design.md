> in storage. `cmd::aggregate` rewires to `build_data_source(...)` like
> `list` did in M2.1. `analyze` write-through + `db ingest` both call
> `upsert_episodes` after `upsert_report`. Estimated ~3 days, ~8-10
> commits, ~12 new tests.

## 1. The problem

M2.1 wired `list`, `mcp-waste`, and `analyze` through `DualPathDataSource`
to read from SQLite cache when available. `cmd::aggregate` was
deliberately excluded because all four `--by` arms (`tool` / `hook` /
`day` / `model`) need the **raw per-call durations** from `Episodes`
to recompute cross-session p50/p95 — averaging per-session percentiles
would be statistically wrong (see `aggregate_by_tool::aggregate_by_tool`
rustdoc).

`SessionDataSource::load_session()` only returns `AnalysisReport`, which
has rollup data (`tool_rank: Vec<ToolRankRow>` with totals) but **not**
the per-call vec needed for percentile pooling. So aggregate stayed on
the single-path adapter route and gets no cache acceleration.

This is the largest remaining gap in M2.1's dual-path story. Users
running `agentprof aggregate --by tool --since 30d` re-parse every
fixture every time, while `list --since 30d` is instant on cache hit.

### 1.1 What aggregate actually needs from Episodes

Verified by grepping callers:

- `aggregate_by_tool` — `episodes.tools[name].calls[*].span` for duration pool
- `aggregate_by_hook` — same shape on `episodes.hooks[name].calls`
- `aggregate_by_day` — `episodes.tools.values()` + `episodes.turns` for daily windowing
- `aggregate_by_model` — `episodes.turns` for per-turn model + token usage
- All arms — `wall::compute_wall(episodes, meta.started_at)` for total wall time

So aggregate needs **the full Episodes structure**, not a slim subset.
A slim "aggregation projection" alternative was rejected during
brainstorm — the maintenance burden of two co-evolving shapes outweighs
the modest blob-size saving.

### 1.2 Brainstorming decisions (recap, 2026-06-09 22:41–22:46)

| # | Question | Decision | Rationale |
|---|---|---|---|
| 1 | Storage layout | **Separate `episodes_json` column** | Explicit, aggregate-only readers skip report deserialization, easier to evolve independently |
| 2 | Trait shape | **Independent `load_episodes(id)` method** | Clean separation, aggregate calls twice (accepts 2× adapter pipeline cost, no caching) |

Brainstorm transcript at terminal turn `2026-06-09T22:41+`. User explicitly
accepted the 2× adapter pipeline cost: *"D1: 独立 load_episodes(id) 方法。
aggregate 调两次（load_session + load_episodes）。Adapter 会两次走 pipeline
（性能损失），Sqlite 两次 SQL（所谓）"*.

## 3. Data model

### 3.1 `core::datasource::SessionDataSource` (trait method addition)

```rust
#[non_exhaustive]
pub trait SessionDataSource: Send + Sync {
    fn name(&self) -> &'static str;
    fn discover(&self, since: Duration) -> Result<Vec<SessionRef>, DataSourceError>;
    fn load_session(&self, id: &str) -> Result<AnalysisReport, DataSourceError>;

    /// NEW in M2.1.1: load per-session Episodes for aggregate's percentile
    /// recomputation.
    ///
    /// Implementations MAY return an empty [`Episodes`] if the underlying
    /// source has no per-call data (e.g. a pre-M2.1.1 SQLite row that was
    /// not re-ingested after the migration to schema_version=2). Aggregate
    /// callers MUST tolerate empty values (no-op skip in percentile pool).
    ///
    /// # Errors
    ///
    /// Same shape as [`Self::load_session`]:
    /// - [`DataSourceError::NotFound`] if the id is unknown
    /// - [`DataSourceError::Adapter`] / [`DataSourceError::Storage`] on
    ///   backend failure
    fn load_episodes(&self, id: &str) -> Result<Episodes, DataSourceError>;
}
```

**No default impl.** Trait is `#[non_exhaustive]` so adding methods isn't
a *breaking* trait-extension in the safe-trait-evolution sense, but all
three internal impls (`AdapterDataSource`, `SqliteDataSource`,
`DualPathDataSource`) must override. There are no external impls — the
trait is single-purpose internal to the workspace.

If a future external implementor lands (unlikely pre-v1.0), a default
impl returning `unimplemented!()` can be added in a non-breaking patch.

### 3.2 Storage schema (migration 002)

`crates/agentprof-storage/migrations/002_episodes_column.sql`:

```sql
-- M2.1.1: episodes blob column for aggregate's per-call/per-turn data.
--
-- Default '{}' so existing M2.1-schema rows remain queryable —
-- load_episodes(id) on an un-reingested row returns
-- Episodes::default() (all empty maps + empty vecs), which aggregate
-- callers gracefully skip (zero contribution to the percentile pool).
-- Cache-mode users get full coverage on the next ingest; store-mode
-- users keep their existing report data and can choose when to backfill.
ALTER TABLE sessions ADD COLUMN episodes_json TEXT NOT NULL DEFAULT '{}';
```

No new indexes. The column is never queried *on* — it's only ever
SELECTed by primary key (`id`) in `load_episodes`.

`rusqlite_migration` already handles ALTER TABLE additively; existing
DBs at schema_version=1 will be upgraded transparently on next
`Db::open_and_migrate`.

### 3.3 New storage public API

`crates/agentprof-storage/src/upsert.rs` (extend existing module):

```rust
/// Persist a session's [`Episodes`] into the `episodes_json` column.
///
/// Independent from [`upsert_report`] — callers must invoke both to
/// fully populate a session (see `cmd::analyze`'s write-through and
/// `cmd::db::ingest::run` for the canonical pairing).
///
/// `ingested_at_secs` is currently unused (the timestamp already lives
/// in `sessions.ingested_at` via the matching `upsert_report` call) but
/// kept as a positional parameter for symmetry with `upsert_report`
/// and to ease future "episodes-changed-but-report-didn't" cache
/// invalidation logic.
///
/// # Errors
/// - [`SqliteError::Serde`] if Episodes JSON encoding fails
/// - [`SqliteError::Rusqlite`] on DB write error
///
/// # Examples
/// ```no_run
/// use agentprof_storage::{Db, upsert::upsert_episodes};
/// use agentprof_core::episode::Episodes;
/// let mut db = Db::open_in_memory().unwrap();
/// let eps = Episodes::default();
/// // (in real use, session row must exist first via upsert_report)
/// // upsert_episodes(&mut db, "abc-123", &eps, 1_700_000_000).unwrap();
/// ```
pub fn upsert_episodes(
    db: &mut Db,
    id: &str,
    episodes: &Episodes,
    ingested_at_secs: i64,
) -> Result<usize, SqliteError>;
```

`crates/agentprof-storage/src/query.rs` (extend existing module):

```rust
/// Load the per-session [`Episodes`] from the `episodes_json` column.
///
/// Returns `Episodes::default()` (empty) for sessions ingested before
/// migration 002 — distinguishable by `id` existing in sessions but
/// `episodes_json` being the default empty blob.
///
/// # Errors
/// - [`SqliteError::Rusqlite`] with `QueryReturnedNoRows` if id is unknown
/// - [`SqliteError::Serde`] if stored JSON cannot be parsed
pub fn load_episodes(db: &Db, id: &str) -> Result<Episodes, SqliteError>;
```

### 3.4 New `SqliteDataSource::load_episodes` impl

Mirrors `load_session` exactly: acquire mutex with poison-recovery
(`unwrap_or_else(PoisonError::into_inner)`), call `query::load_episodes`,
map `QueryReturnedNoRows` → `DataSourceError::NotFound`, else wrap into
`Storage` variant via `map_storage` helper.

### 3.5 New `AdapterDataSource::load_episodes` impl

Mirrors `load_session` exactly: re-discover the root, find the session
by id, call `adapter.load_session(&sref)` for `RawSession`, derive
episodes, return. **No sharing with `load_session`'s analyze step** —
two independent invocations means two full pipeline runs. Per
brainstorm decision D1.

The audit-flagged O(N²) hot loop in `db ingest --all` is unaffected:
ingest uses the bypass method `load_session_by_ref(&AdapterRef)` for
the report side and will get a new `load_episodes_by_ref(&AdapterRef)`
bypass for symmetry (see §4.3 below).

### 3.6 New `DualPathDataSource::load_episodes` impl

Same shape as `load_session`: try storage first; on `NotFound` (or any
other error), fall back to adapter. No merge_refs equivalent — episodes
aren't enumerated like refs; they're loaded per-id.

## 4. CLI integration

### 4.1 `cmd::aggregate::run` refactor

Three categories of change:

**(a)** Replace direct `CopilotAdapter` construction with the standard
factory pattern used by `list` / `mcp-waste`:

```rust
let storage_cfg = resolve_storage_config(...)?;
let (ds, warnings_handle) = build_data_source(agent_name, &root, &storage_cfg, cli.no_cache)?;
```

**(b)** Add explicit `sort_by(Reverse(started_at_ms), then id)` after
discover — matches M2.1 CI-fix invariant for `list` so ordering is
runner-independent.

**(c)** Per-session loop calls **both** methods:

```rust
let mut reports = Vec::with_capacity(refs.len());
let mut episodes_vec = Vec::with_capacity(refs.len());
let mut failure_count = 0usize;
for sref in &refs {
    let report = match ds.load_session(&sref.id) { Ok(r) => r, Err(e) => { warn(e); failure_count += 1; continue; } };
    let episodes = match ds.load_episodes(&sref.id) {
        Ok(e) => e,
        Err(e) => {
            tracing::warn!(session = %sref.id, error = %e, "load_episodes failed; falling back to empty");
            agentprof_core::episode::Episodes::default()
        }
    };
    reports.push(report);
    episodes_vec.push(episodes);
}
```

**Failure mode**: a `load_episodes` failure does NOT abort the row — it
substitutes empty Episodes (zero contribution to percentile pool) and
logs the failure. Matches the "single session failure doesn't kill
command" project rule (`§7.8`).

After render: drain `warnings_handle`, emit per spec §7.3 format.

### 4.2 `cmd::analyze` write-through extension

Current M2.1 code:

```rust
if !cli.no_cache {
    if let Ok(mut db) = Db::open_and_migrate(&storage_cfg.path) {
        let _ = upsert_report(&mut db, &report, &raw.path, now_secs);
    }
}
```

After M2.1.1:

```rust
if !cli.no_cache {
    if let Ok(mut db) = Db::open_and_migrate(&storage_cfg.path) {
        if let Err(e) = upsert_report(&mut db, &report, &raw.path, now_secs) {
            tracing::warn!(error = %e, "write-through upsert_report failed");
        } else if let Err(e) = upsert_episodes(&mut db, &report.meta.id, &episodes, now_secs) {
            tracing::warn!(error = %e, "write-through upsert_episodes failed");
        }
    }
}
```

Same soft-fail semantics. The `else if` ordering matters: don't try to
write episodes for a session whose parent row failed.

### 4.3 `cmd::db::ingest::run` extension

For each session in the ingest loop:

```rust
match adapter_ds.load_session_by_ref(&sref) {
    Ok(report) => {
        let episodes = adapter_ds.load_episodes_by_ref(&sref)
            .unwrap_or_else(|e| {
                tracing::warn!(session = %sref.id, error = %e, "load_episodes failed; storing empty");
                Episodes::default()
            });
        if upsert_report(&mut db, &report, &sref.path, now_secs).is_ok() {
            let _ = upsert_episodes(&mut db, &report.meta.id, &episodes, now_secs);
        }
    }
    Err(e) => { /* failure_count++; continue */ }
}
```

`load_session_by_ref` already exists from M2.1 audit P1-3 (skips the
discover scan). **NEW** for M2.1.1: `load_episodes_by_ref(&AdapterRef)`
mirror — reuses an already-discovered ref to skip redundant discovery.

### 4.4 New global flags / subcommand surfaces

**None.** M2.1.1 reuses every existing CLI flag (`--no-cache` /
`--storage-path` / `--quiet`) and every existing subcommand. The change
is purely additive on the trait + storage layer, with `aggregate` and
two existing write paths picking it up.

## 6. ADR (deferred to T-final)

**ADR-0020 — aggregate dual-path via separate Episodes storage**

- Status: Accepted (2026-06-09)
- Context: aggregate stayed single-path in M2.1; closure needed for v0.2.x
- Considered: (A) Episodes hoisted into AnalysisReport blob;
  (B) aggregation-projection subset struct; **(C) separate column + trait method** (chosen)
- Rationale: explicit storage layout, trait method symmetric with load_session, no
  AnalysisReport bloat, accepts 2× adapter pipeline cost for simplicity
- Consequences:
  + aggregate gets cache acceleration matching list / mcp-waste
  + Episodes evolution stays internal to storage's blob format
  - AdapterDataSource does 2× pipeline for aggregate (acceptable; ~3s vs ~1.5s on 22 fixtures)
  - +1 trait method (3 impls must override)
  - migration 002 adds default-empty episodes_json column

## 8. Out of scope (this milestone)

| Item | Why deferred |
|---|---|
| AdapterDataSource internal caching for load_episodes | user explicitly chose D1 (accept 2× cost); revisit if perf data shows it matters |
| Episodes incremental update (write only changed tools) | YAGNI; full overwrite matches upsert_report and is fine for sub-200KB blobs |
| Down-migration 002 → 001 | matches 001 policy (none); manual sqlite hack if ever needed |
| Episodes JSON compression (zstd / lz4) | YAGNI; SQLite WAL handles ~100MB DBs fine; revisit at v0.3+ if cache grows past 1GB |
| Episodes schema versioning | tied to existing `sessions.schema_version` — if Episodes shape changes, bump that whole column and force re-ingest (already supported) |
| Separate `episodes` migration as own crate feature | overengineering; one ALTER is fine |

**Required to merge**:
- All M2.1 snapshot tests still pass byte-identically

**Acceptance criteria** (verifiable via `agentprof db ingest --all` +

- Cache hit → identical stdout to `--no-cache` run
- Cache miss with stale mtime → stderr warn line per spec §7.3
- Cache miss with absent `episodes_json` → aggregate completes without
  panic, percentile pool lacks that session's data (correctness:
  result is `n-1`-session aggregation; not a hard failure)
