## 1. The problem

After M1.7 release every read command (`list`, `aggregate`,
`mcp-waste`) re-scans `~/.copilot/projects/**/events.jsonl` end-to-end
and re-runs the full episode + analyze pipeline. For a user with 30+
days of history that's 100+ files re-parsed per `agentprof list`
invocation. Dogfooding on a moderate-history laptop already runs ~2-4
seconds per command; heavy users will hit 10s+ which crosses the
"feels broken" UX threshold.

A second problem: **session loss**. Copilot CLI prunes its own
`events.jsonl` files after some retention period. agentprof has no
way to preserve historical analysis once the source `jsonl` is
collected by the upstream pruner.

A third problem: M2.2 (OTLP receiver) needs SOMEWHERE to write the
ingested telemetry, and Web dashboard (potential M2.3) needs a query
backend. Both require this layer first.

### 1.1 What v0.1.x already has (don't double-count)

- `agentprof-storage` crate **exists** (compiles, listed in workspace)
  but is a **STUB** — README explicitly says "no implementation has
  shipped"
- `rusqlite` is in `[workspace.dependencies]` with `bundled` feature
- `architecture.md` §9 has a 3-table DDL sketch (reconciled below)
- `docs/architecture.md` §10 has a `[storage]` config TOML snippet
  (will extend, see §6)

### 1.2 Maintainer's environment (2026-06-09 audit)

- No existing SQLite db on disk
- No prior agentprof persistence — first run will be `db init` then
  full `db ingest --all` to backfill
- Has ~20+ Copilot sessions across 4 weeks; sufficient for stress test

## 2. Brainstorming decisions (recap — 2026-06-09)

| # | Question | Decision | Rationale |
|---|---|---|---|
| 1 | DB role | **Hybrid** — default cache, opt-in store | YAGNI for "always store"; cache → store upgrade trivially additive; store → cache impossible without data loss |
| 2 | Schema philosophy | **3-table normalized** | SQL-friendly for cross-session queries; matches arch §9 sketch; future ADR-able as JSON-blob alternative if normalized proves too rigid |
| 3 | Read source | **Dual-path** (adapter + DB always) | Maintainer values correctness/visibility over speed at v0.2.0; perf tuning is v0.3.0 work |
| 4 | Conflict resolution | **Warn + adapter wins** | `jsonl` is source-of-truth; DB is derivative; user-visible warns surface stale-cache bugs early |
| 5 | Code organization | **`SessionDataSource` trait** in `agentprof-core` | Symmetric to existing `Adapter` trait; future-proofs for OTLP impl; leaf-crate rule satisfied |

Full design conversation: terminal turns 2026-06-09 13:00–13:24.

### 3.2 `SessionDataSource` trait

```rust
// crates/agentprof-core/src/datasource.rs (new module)
use std::time::Duration;
use crate::{AnalysisReport, model::AgentName};

/// A source of analyzed session data. Implemented by file adapters
/// (parsing `events.jsonl`), the SQLite cache/store, and the
/// dual-path composer that fans out to both.
#[non_exhaustive]
pub trait SessionDataSource: Send + Sync {
    /// Human-readable name for warnings and traces (e.g. "adapter:copilot", "sqlite", "dual").
    fn name(&self) -> &'static str;

    /// Enumerate sessions modified within the time window. Cheap;
    /// must not load full reports. Returns `SessionRef` summaries.
    fn discover(&self, since: Duration) -> Result<Vec<SessionRef>, DataSourceError>;

    /// Load full `AnalysisReport` for a single session.
    fn load_session(&self, id: &str) -> Result<AnalysisReport, DataSourceError>;
}

#[non_exhaustive]
pub struct SessionRef {
    pub id: String,
    pub agent: AgentName,
    pub started_at_ms: Option<i64>,
    pub raw_path: Option<std::path::PathBuf>,
    pub raw_mtime_ms: Option<i64>,
    pub source: &'static str,           // "adapter" | "sqlite" | "dual"
}

#[derive(thiserror::Error, Debug)]
#[non_exhaustive]
pub enum DataSourceError {
    #[error("session not found: {id}")]
    NotFound { id: String },
    #[error("adapter error in {source}: {underlying}")]
    Adapter { source: &'static str, #[source] underlying: Box<dyn std::error::Error + Send + Sync> },
    #[error("storage error in {source}: {underlying}")]
    Storage { source: &'static str, #[source] underlying: Box<dyn std::error::Error + Send + Sync> },
}
```

**Why `&'static str` for `source`**: avoid string allocations on hot path;
the set is closed (adapter agent names + "sqlite" + "dual").

**Why `Box<dyn Error>` for `underlying`**: lets adapters/storage keep
their own error types (`AdapterError`, `SqliteError`) without core
having to know them — preserves leaf rule.

### 3.3 Dependency-graph verification (no cycles)

```
core    ◀──── adapters     (uses Adapter, AnalysisReport, SessionDataSource)
core    ◀──── storage      (uses AnalysisReport, SessionDataSource, model types)
core    ◀──── tui          (unchanged)
core    ◀──── cli          (uses everything)
adapters ◀─── cli
storage  ◀─── cli
tui      ◀─── cli
```

No new cycles. `storage` does NOT depend on `adapters` (the dual-path

## 5. SQLite Schema (final DDL)

**File**: `crates/agentprof-storage/migrations/001_initial.sql`

```sql
-- agentprof v0.2.0 M2.1 initial schema (schema_version=1)

CREATE TABLE sessions (
    id                    TEXT    PRIMARY KEY,
    agent                 TEXT    NOT NULL,              -- 'copilot' | 'claude' | 'codex'
    dominant_model        TEXT,                          -- nullable: from model_metrics by total tokens
    started_at            INTEGER,                       -- unix epoch (ms)
    duration_ms           INTEGER,
    raw_path              TEXT NOT NULL,                 -- absolute source jsonl path
    raw_mtime             INTEGER NOT NULL,              -- mtime (ms) — drives dual-path freshness
    total_input_tokens    INTEGER,
    total_output_tokens   INTEGER,
    total_cache_read      INTEGER,
    total_cache_creation  INTEGER,
    schema_version        INTEGER NOT NULL DEFAULT 1,    -- analyzer version; bumped breaking-ly to force recompute
    ingested_at           INTEGER NOT NULL,              -- write time (ms)
    analysis_report_json  TEXT NOT NULL                  -- complete AnalysisReport serde JSON (disaster recovery)
);
CREATE INDEX idx_sessions_started      ON sessions(started_at DESC);
CREATE INDEX idx_sessions_agent_started ON sessions(agent, started_at DESC);

CREATE TABLE tools_loaded (
    session_id        TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    tool_name         TEXT NOT NULL,
    source            TEXT NOT NULL,                     -- 'builtin' | 'mcp:<server>' | 'skill:<name>'
    call_count        INTEGER NOT NULL,
    total_duration_ms INTEGER NOT NULL,
    tokens            INTEGER,                           -- M1.6.6 token cost
    token_source      TEXT,                              -- 'heuristic' | 'sidecar'
    PRIMARY KEY (session_id, tool_name)
);
CREATE INDEX idx_tools_call_count ON tools_loaded(session_id, call_count DESC);

CREATE TABLE turn_buckets (
    session_id      TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    turn_index      INTEGER NOT NULL,
    input_tokens    INTEGER,
    output_tokens   INTEGER,
    cache_read      INTEGER,
    cache_creation  INTEGER,
    model           TEXT,
    PRIMARY KEY (session_id, turn_index)
);
```

**Index choices**:
- `idx_sessions_started` — `list --since 7d` is the hottest query
- `idx_sessions_agent_started` — multi-agent filter once M3.1/3.2 land
- `idx_tools_call_count` — `aggregate --by tool` low-utilization scan

**`PRAGMA` set on every open**:
- `journal_mode = WAL` (concurrent read + serialized write)
- `synchronous = NORMAL` (sync on checkpoint, not per-tx — fine for cache)
- `foreign_keys = ON` (cascade deletes)

## 6. Hybrid mode

### 6.1 Mode semantics

| Aspect | Cache (default) | Store (opt-in) |
|---|---|---|
| Trigger | no config / `mode = "cache"` | `[storage] mode = "store"` |
| Default path | `$XDG_CACHE_HOME/agentprof/cache.sqlite` | `$XDG_DATA_HOME/agentprof/store.sqlite` |
| Typical Linux path | `~/.cache/agentprof/cache.sqlite` | `~/.local/share/agentprof/store.sqlite` |
| `rm <path>` impact | safe — rebuilt on demand | **data loss** — pruned jsonl history gone |
| Auto-prune | enabled (default 30 days, configurable) | disabled |
| User backup expected | no | yes (rsync / restic / similar) |
| analyze overwrite | allowed (latest wins) | allowed (latest wins) — never "append" |
| Suitable for | individuals dogfooding | teams / multi-month dogfood / audit trail |

### 6.2 Config schema

`~/.config/agentprof/config.toml` extension:

```toml
[storage]
# "cache" (default) | "store"
mode = "cache"

# Override default path (XDG-derived if absent)
# path = "~/.cache/agentprof/cache.sqlite"

# Cache mode only — ignored in store mode
auto_prune_days = 30
```

All three fields are optional; defaults applied at parse time.

### 6.3 CLI override

| Flag | Purpose | Notes |
|---|---|---|
| `--storage-path <PATH>` | Override resolved DB path | Useful for `db export` to alt file, multi-tenant CI |
| `--no-cache` | Skip DB entirely (fall back to single-path adapter) | Debugging; equivalent to no-storage operation |
| ❌ `--storage-mode {cache,store}` | NOT added | Mode is "set and forget" — switching it should be a config edit, not an ad-hoc flag |

Resolution precedence: `--storage-path` > `[storage].path` > XDG default for active mode.

## 7. Read path: dual-path query lifecycle

### 7.1 Flow

```
user: agentprof list --since 7d
        │
        ▼
DualPathDataSource::discover(7d)
        │
        ├─────────────────┬─────────────────┐
        ▼                 ▼                 │
adapter.discover(7d)  storage.discover(7d) │
   (jsonl scan)      (SELECT FROM sessions │
                      WHERE started_at>...)│
        │                 │                │
        └─────────┬───────┘                │
                  ▼                         │
            merge layer (set-union)         │
                  │                         │
        ┌─────────┼─────────┐               │
        ▼         ▼         ▼               │
   adapter    both id    storage            │
    only        ↓         only              │
   (take)   field eq?    (take)             │
                ↓                           │
        ┌───────┴────────┐                  │
        ▼                ▼                  │
       yes              no                  │
    (silent           (warn +               │
    adapter)          adapter +             │
                    async re-upsert) ───────┘
                  │
                  ▼
            Vec<SessionRef> (deduplicated, adapter-sourced where conflict)
```

### 7.2 Diff judgment fields

When session_id is in **both**, compare:

| Field | Mismatch interpretation |
|---|---|
| `raw_mtime` | jsonl was modified after last DB ingest — adapter has fresher data |
| `schema_version` | analyzer logic changed — DB row is stale, force re-upsert |
| `total_input_tokens` | numeric divergence (rare; usually means analyzer bug) |
| `started_at` | should NEVER differ; if it does, emit `tracing::error!` and use adapter |

The warning **only fires on actual divergence**, not on "both same".
For mtime-only difference (DB just older), warn is "info" level not
"warn"; for token-count divergence, warn is full "warn" level.

### 7.3 Warning sink (output destination)

| Caller context | Sink |
|---|---|
| TTY stderr (default) | stderr line, compact format |
| `--export json` / `--export csv` | stderr (stdout stays machine-readable) |
| `--export tui` / `watch` | tracing event → `$XDG_STATE_HOME/agentprof/agentprof.log` (existing M1.6.4 infra) |
| `--export md` / `--export html` | stderr |

Compact format example:
```
agentprof: warn: session abc123: raw_mtime newer in adapter (2026-06-09T...) vs DB (2026-06-08T...); using adapter; will re-upsert
```

`--quiet` global flag (NEW) suppresses the warning line (still logged).

### 7.4 Async re-upsert

Triggered on adapter-wins outcome. Implementation: `std::thread::spawn`
fires `storage.upsert_report(&new_report)` in background. Best-effort —
failure logged but doesn't block command. No `tokio`.

## 8. Write path

| Trigger | Behavior | `--no-cache` effect |
|---|---|---|
| `agentprof analyze` | **Write-through**: after analysis, `storage.upsert_report(&report)` | skip write |
| `list`/`aggregate`/`mcp-waste` dual-path "adapter wins" | **Async re-upsert** in background thread | skip write |
| `agentprof watch` | NO automatic write per refresh (avoid high-freq disk churn); final flush on exit | watch never writes |
| `agentprof db ingest --agent X` | **Batch upsert** with progress bar; no report rendering | n/a (explicit command) |

`upsert_report` semantics: latest wins, full overwrite of all 3 tables for that session (atomic via single transaction, cascade-replace).

## 9. CLI surface changes

### 9.1 New global flags (apply to all subcommands)

| Flag | Type | Purpose |
|---|---|---|
| `--no-cache` | bool | Skip all DB I/O; dual-path → single-path adapter |
| `--storage-path <PATH>` | PathBuf | Override DB path (rare; mostly testing/export) |
| `--quiet` | bool | Suppress dual-path warning lines on stderr |

`--quiet` is new but useful beyond M2.1; introduced here, may grow scope post-v0.2.0.

### 9.2 New `agentprof db` subcommand family

```
agentprof db <SUBCOMMAND>

Subcommands:
  init        Create DB + run migrations (idempotent)
  stats       Show DB statistics (size, row counts, mode, path, oldest/newest session)
  ingest      Batch-import sessions into DB without rendering a report
  prune       Delete sessions older than N days (cascade)
  vacuum      Run SQLite VACUUM to compact the file
  export      Export a single session as JSON / JSONL from DB
```

#### 9.2.1 `db init`
- Flags: none beyond global
- Behavior: open DB at resolved path (creates parent dir), run migrations
- Idempotent — silently no-ops if already at HEAD migration
- Exit: 0 success / 1 if user lacks write permission

#### 9.2.2 `db stats`
- Flags: `--export {table,json}` (default `table`)
- Output (table): mode / path / file size / total sessions / oldest / newest / per-table row count
- Useful for `agentprof db stats | grep size` in dotfiles dashboards

#### 9.2.3 `db ingest`
- Flags: `--agent <X>` (required) + `--since <DURATION>` | `--all` | `--session <ID>`
- Progress: stderr progress bar via `indicatif` crate (NEW workspace dep — add in T2)
- Stops on first per-session parse error; prints summary at end

#### 9.2.4 `db prune`
- Flags: `--before <DURATION>` (required; e.g. `30d`, `6mo`) + `--dry-run`
- `--dry-run` lists what WOULD be deleted, no DB write
- Cascade-deletes `tools_loaded` + `turn_buckets` rows automatically (FK on)

#### 9.2.5 `db vacuum`
- Flags: none
- Behavior: `VACUUM` SQLite — reclaims free pages
- Prints before/after size

#### 9.2.6 `db export <SESSION_ID>`
- Flags: `--format json|jsonl` (default `json`) + `--output <PATH>` (default stdout)
- For `jsonl`: one row per `turn_buckets` row + one header row for session metadata
- For `json`: emits the stored `analysis_report_json` verbatim

### 9.3 NOT in scope (post-v0.2.0)

- ❌ `db query "<SQL>"` — YAGNI; users can `sqlite3 ~/.cache/.../cache.sqlite` directly
- ❌ `db migrate` (manual migration trigger) — `init` and every command auto-migrates
- ❌ `db import <FILE>` (round-trip from `db export`) — symmetric but unused so far
- ❌ Multi-machine sync / replication

## 10. Migration tooling + concurrency model

### 10.1 Migrations

- Crate: [`rusqlite_migration`](https://crates.io/crates/rusqlite_migration) — pure Rust, no build.rs, idempotent. **NEW workspace dep — add to `[workspace.dependencies]` in T2.**
- Files in `crates/agentprof-storage/migrations/NNN_<name>.sql`
- `include_str!` at compile time — migrations ship inside the binary (no runtime file dep)
- `Db::open_and_migrate(path) -> Result<Db>` always runs migrations to HEAD before returning

### 10.2 Connection model

| Caller | Connection lifetime |
|---|---|
| Single CLI invocation (`analyze`, `list`, etc.) | open at command start, drop at end (RAII) |
| `agentprof watch` | one connection held for the whole watch session |
| `agentprof db ingest --all` | one connection wrapping the batch transaction |
| Unit tests | `:memory:` per-test |

NO connection pool (`r2d2`, `deadpool`) — CLI invocations are short and serial; pool overhead unjustified.

### 10.3 Async re-upsert

`std::thread::spawn` from inside `DualPathDataSource::discover` after
the adapter-wins decision. The spawned thread opens its OWN connection
(WAL allows this), runs `upsert_report`, drops connection. Main thread
returns to caller immediately. Failure logged via `tracing::warn!`.

NO `tokio` — keeps CLI startup time low (no runtime init) and avoids
async coloring through the existing sync code.
