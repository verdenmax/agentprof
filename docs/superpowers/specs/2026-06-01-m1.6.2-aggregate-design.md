```sh
# Across all recent sessions, rank tools by total time
```

## 2. Locked decisions (from brainstorming)

| # | Decision | Rationale |
|---|---|---|
| D-1 | Full PRD scope: 4 `--by` keys × 4 `--export` formats (md/json/csv/html). TUI deferred. | User choice — ship the complete value at once |
| D-2 | **Sequential parsing** for MVP; rayon parallelization deferred to a future perf milestone | User choice — keep MVP simple; 100 sessions × 100 ms = 10s is acceptable |
| D-3 | **TUI export deferred to M1.6.3** (combined with `watch` mode, which naturally needs a live-aggregate view) | User choice — avoid duplicate TUI scaffolding |
| D-4 | **MCP "waste" analysis NOT in scope** — deferred to a new milestone **M1.6.5** | User choice — events.jsonl doesn't carry tool registration; computing "loaded but never called" needs `.copilot/mcp.json` parsing, which is a separate piece of work |
| D-5 | `--by day` adds `utilization_pct` field + automatic warn color when below threshold | User choice — utilization (`tool_duration / wall_duration`) is the headline metric for time-series analysis |
| D-6 | New CLI flag `--low-utilization-threshold` (default 20, range 0-100) controls the warning threshold | User choice — lets advanced users tune |
| D-7 | **Generic `AggregateReport<B>`** + outer enum `AnyAggregateReport` for serde/CLI boundary | User choice — type-safe bucket data + simple serialization boundary |
| D-8 | New workspace dep `csv = "1"` (NOT serde feature; we write headers + rows directly) | Only new dep; well-maintained, < 1 MB binary impact |
| D-9 | Day bucket uses **UTC dates** (no system timezone) | events.jsonl timestamps are RFC3339 UTC; consistent with how Speedscope timestamps are anchored (M1.6.4 D-10) |
| D-10 | Per-session parse failures **degrade gracefully**: stderr summary; report contains successful sessions only; all-fail exits `DataError(2)` | Mirrors M1.6.1 `list` behavior |
| D-11 | Empty result (zero sessions match window) exits 0 + stderr message; not an error | Mirrors `list` |
| D-12 | Model bucket "session model" = the model active at the first turn (single representative value per session) | Simple; if user switches models mid-session, multi-model attribution is a future enhancement |
| D-13 | New ADR-0008 documents `AggregateReport<B>` design, `AnyAggregateReport` enum, and utilization metric semantics | Significant new public type + cross-session semantics warrant their own ADR |

## 3. Scope

### 3.1 In scope

1. `agentprof aggregate` subcommand with flags:
   - `--agent <copilot>` (default `copilot`; M1.6.2 supports only copilot per existing adapter coverage)
   - `--root <dir>` (override adapter default)
   - `--by <tool|mcp-server|day|model>` (required — no default; user must pick)
   - `--since <Nd|Nh|Nm|Ns|all>` (default `30d`)
   - `--limit <N>` (default `0` = unlimited; caps bucket count in the final report)
   - `--export <md|json|csv|html>` (default `md`)
   - `--output <path>` (write to file instead of stdout)
   - `--low-utilization-threshold <0-100>` (default `20`; only affects `--by day` warn color)
2. `agentprof-core::analyzer::aggregate` module containing:
   - `AggregateReport<B>` generic struct
   - `AnyAggregateReport` enum at the serde boundary
   - `AggregateKey` enum (Tool / McpServer / Day / Model)
   - 4 bucket structs (`ToolBucket`, `McpServerBucket`, `DayBucket`, `ModelBucket`)
   - 4 aggregator functions
3. `agentprof-cli::cmd::aggregate` orchestrator that loads N sessions sequentially, runs the aggregator, dispatches to renderer
4. 4 new renderer modules in `agentprof-cli::cmd::format::aggregate_{md,json,csv,html}`
5. New askama template `aggregate.html` (separate from M1.6.4's `report.html`)
6. New synthetic fixture set covering multi-session scenarios:
   - `with-many-sessions/` containing 3-5 small session directories that span 2 different days, 2 different models, multiple tools, and ≥1 MCP server
7. ADR-0008 documenting the design
8. L1+L2+L3 docs sync
9. ~10 unit tests + 4 integration tests + 3 snapshot tests (md/json/html)

### 3.2 Out of scope

| Item | Why not |
|---|---|
| `--export tui` (cross-session TUI browser) | D-3 — deferred to M1.6.3 alongside `watch`, which naturally needs the live-aggregate view |
| MCP server "waste" analysis (loaded but never called) | D-4 — new M1.6.5 milestone; needs `.copilot/mcp.json` parsing |
| Parallel session parsing via rayon | D-2 — deferred to a future perf milestone |
| Drill-down from aggregate row to single session (`aggregate ... drill <bucket>`) | Future M1.6.6+; users can use `agentprof analyze --session <id>` for now |
| Cross-adapter aggregation (mixing Claude + Codex + Copilot in one report) | Phase 3+ — only Copilot adapter ships today |
| `--by hour` / `--by week` / `--by month` granularities | Future; `--by day` covers the common case |
| Multi-model attribution per session (a session that switched models gets one bucket per model) | D-12 — simple representative-value semantics for MVP |
| Tokenizer-based weights | Phase 2 — no tokenizer until then |
| Custom output columns (`--columns p99,latency`) | Future; default columns sufficient for MVP |
| Per-bucket filtering (`--include-tool bash`) | Future; users can grep the output |

## 4. CLI surface

### 4.1 ExportFormat for aggregate

`cli::cmd::aggregate.rs`:

```rust
#[derive(ValueEnum, Debug, Clone, PartialEq)]
pub enum AggExportFormat {
    /// Markdown table to stdout/file (default).
    Md,
    /// JSON serialization of AnyAggregateReport. Whole report, structured.
    Json,
    /// CSV with headers (one row per bucket).
    Csv,
    /// Self-contained static HTML report (no JS), askama-templated.
    Html,
    // Tui deferred to M1.6.3
}
```

Note: a separate enum from `analyze::ExportFormat` because aggregate doesn't have a TUI variant (yet) and has CSV (which analyze doesn't). Avoids confusion + lets each subcommand evolve independently.

### 4.2 Behavior matrix

| Flag combo | Behavior |
|---|---|
| `--by tool` (defaults) | Aggregate all sessions in last 30 days, all tools; md table to stdout |
| `--by tool --export json` | Same data, JSON to stdout |
| `--by day --since all --output day.csv --export csv` | Whole history, CSV to file |
| `--by day --low-utilization-threshold 15` | Highlight days < 15% utilization (instead of default 20) |
| `--by mcp-server --since 7d` | Only MCP server buckets; sessions in last 7 days |
| `--limit 10` | Cap bucket count to top 10 (sorted per the key's natural metric — see §6) |
| Invalid `--by foo` | Clap rejects with help message |
| Zero sessions match | exit 0; stderr `"no sessions matching --since=...; tried <path>"` |
| All sessions fail to parse | exit `DataError(2)`; stderr lists each failure |
| `--export tui` | clap rejects (not a variant in M1.6.2) — user message points to M1.6.3 |

### 4.3 Exit codes

Unchanged from M1.4: `0` success / `1` user error / `2` data error / `3` output error / `130` SIGINT. Single-session parse failures don't change the exit code unless ALL sessions failed (DataError).

## 5. Data model

### 5.1 Generic `AggregateReport<B>` (per D-7)

```rust
// agentprof-core::analyzer::aggregate::mod.rs

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[non_exhaustive]
pub struct AggregateReport<B> {
    /// Which key this report was aggregated by.
    pub by: AggregateKey,
    /// Time window upper bound resolved from `--since` argument.
    pub since: chrono::Duration,
    /// Number of sessions actually included.
    pub session_count: usize,
    /// Number of sessions skipped due to parse error.
    pub failure_count: usize,
    /// Sum of all included session wall-clock durations.
    pub total_wall_duration: chrono::Duration,
    /// Per-bucket rows, type-safe per B. Sorted by the natural metric for the
    /// key (see §6).
    pub buckets: Vec<B>,
}
```

### 5.2 Outer enum at serde/CLI boundary

```rust
/// Type-erased wrapper for serialization + CLI dispatch.
/// Internal pipelines use concrete `AggregateReport<X>` for type safety.
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(tag = "by", rename_all = "snake_case")]
#[non_exhaustive]
pub enum AnyAggregateReport {
    Tool(AggregateReport<ToolBucket>),
    McpServer(AggregateReport<McpServerBucket>),
    Day(AggregateReport<DayBucket>),
    Model(AggregateReport<ModelBucket>),
}
```

### 5.3 `AggregateKey` enum

```rust

#[serde(rename_all = "snake_case")]
```

### 5.4 Bucket types

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[non_exhaustive]
pub struct ToolBucket {
    pub name: String,                       // e.g. "bash", "mcp__github__create_pr"
    pub source: ToolSource,                 // re-use M1.2 type
    pub call_count: usize,                  // sum across all sessions
    pub success_count: usize,
    pub failure_count: usize,
    pub total_duration: chrono::Duration,
    pub p50_duration: chrono::Duration,     // re-computed across pooled per-call durations
    pub p95_duration: chrono::Duration,
    pub session_count: usize,               // distinct sessions that used this tool
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[non_exhaustive]
pub struct McpServerBucket {
    pub server: String,                     // e.g. "github"
    pub tool_count: usize,                  // distinct tool names from this server
    pub call_count: usize,                  // sum across all of this server's tools
    pub failure_count: usize,
    pub total_duration: chrono::Duration,
    pub session_count: usize,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[non_exhaustive]
pub struct DayBucket {
    pub date: chrono::NaiveDate,            // UTC date (D-9)
    pub session_count: usize,
    pub total_wall_duration: chrono::Duration,
    pub total_tool_duration: chrono::Duration,
    pub total_output_tokens: u64,
    /// utilization = total_tool_duration / total_wall_duration × 100
    pub utilization_pct: f32,
    /// True when utilization_pct < threshold (CLI passes the threshold in).
    pub is_low_utilization: bool,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[non_exhaustive]
pub struct ModelBucket {
    pub model: String,
    pub session_count: usize,
    pub turn_count: usize,                  // sum across sessions
    pub total_output_tokens: u64,
    pub total_duration: chrono::Duration,
}
```

```rust
// agentprof-core::analyzer::aggregate::group_by_model

```

### 5.6 Invariants

- `reports.len() == episodes_per_report.len()`. Aggregator panics on mismatch (programmer error, not user input).
- `session_count` in the report is `reports.len()` — caller pre-filters failed sessions.
- `total_wall_duration` is the sum across all reports' wall-clock spans (from `meta.started_at` to last event time per-report).
- `buckets` is sorted by the key's natural metric (see §6.x for each key) and truncated to `--limit N` if `N > 0`.

## 6. Aggregation algorithms

### 6.1 `--by tool` (ToolBucket)

```
1. For each (report, episodes):
   - For each ToolRankRow in report.tool_rank:
       - upsert bucket by (row.name, row.source)
       - bucket.call_count += row.call_count
       - bucket.success_count += row.success_count
       - bucket.failure_count += row.failure_count
       - bucket.total_duration += row.total_duration
       - bucket.session_count += 1  (this session used the tool)
       - collect all per-call durations into a pool for percentile recomputation
2. After all reports processed:
   - Re-compute p50/p95 per bucket from the pooled durations
   - Sort buckets by total_duration descending (mirrors single-session ToolRank)
   - Truncate to --limit
```

Sort key: `total_duration` desc (most expensive tools first).

### 6.2 `--by mcp-server` (McpServerBucket)

```
1. For each (report, episodes):
   - For each ToolRankRow whose source is ToolSource::Mcp { server }:
       - upsert bucket by server
       - bucket.call_count += row.call_count
       - bucket.failure_count += row.failure_count
       - bucket.total_duration += row.total_duration
       - bucket.tool_count: track set of distinct row.name
       - bucket.session_count: track set of distinct session this server appeared in
2. After all reports:
   - bucket.tool_count = len of distinct-tools set
   - bucket.session_count = len of distinct-sessions set
   - Sort by total_duration desc
```

Sort key: `total_duration` desc.

### 6.3 `--by day` (DayBucket) — with utilization (per D-5/D-6)

```
1. For each (report, episodes):
   - date = meta.started_at.date_naive()  (UTC; D-9)
   - upsert bucket by date
   - bucket.session_count += 1
   - bucket.total_wall_duration += compute_wall_duration(episodes, meta)
     // wall = last event time - session start
   - bucket.total_tool_duration += sum of all ToolCall span durations
   - bucket.total_output_tokens += sum of TurnSummaryRow.output_tokens
2. After all reports:
   - For each bucket:
       util = total_tool_duration / total_wall_duration × 100
       bucket.utilization_pct = util as f32 (clamped to [0.0, 100.0])
       bucket.is_low_utilization = util < low_util_threshold_pct
   - Sort buckets by date ascending (time series natural order)
```

Sort key: `date` asc (time series order).

### 6.4 `--by model` (ModelBucket)

```
1. For each (report, episodes):
   - model = report.turn_summary[0].model  (D-12: first-turn model)
     // skip session if first-turn model is None
   - upsert bucket by model
   - bucket.session_count += 1
   - bucket.turn_count += report.turn_summary.len()
   - bucket.total_output_tokens += sum of TurnSummaryRow.output_tokens
   - bucket.total_duration += compute_wall_duration(episodes, meta)
2. Sort by session_count desc (most-used model first)
```

Sort key: `session_count` desc.

### 6.5 Percentile recomputation note

Single-session `ToolRankRow.p50/p95` is computed across that session's calls. When aggregating, **we cannot simply average** p50 values — that would be statistically wrong. We must re-compute from the pooled per-call durations.

This means the aggregator needs access to per-call `Duration` data, not just the summary p50/p95. Options:

- **Option A**: pass `&[Episodes]` alongside `&[AnalysisReport]` (current signature). Pool durations from `episodes.tools[name].calls[*].span.duration()`.
- **Option B**: enrich `ToolRankRow` to carry `Vec<Duration>` per row. Less efficient (one Vec per row × hundreds of rows × hundreds of sessions).

**Decision**: Option A. Already in the signature.

## 7. Loading + CLI dispatch flow

### 7.1 Pipeline

```
cmd::aggregate::run(cmd) {
    1. validate --low-utilization-threshold in [0.0, 100.0]
    2. resolve adapter from --agent (M1.6.2 only copilot)
    3. resolve root: cmd.root.or(adapter.default_session_root())?
    4. discover_sessions(root) → Vec<SessionRef>
    5. filter by --since: keep where modified_at >= now - since_duration
       if empty: stderr "no sessions matching --since=..."; exit 0
    6. for each session (sequential):
        match load_and_analyze(adapter, sref) {
            Ok((report, episodes)) => collect into reports/episodes vecs
            Err(e) => stderr "warning: failed to parse session <id>: <e>"
                      increment failure_count, continue
        }
    7. if reports.is_empty() && failure_count > 0:
           exit DataError(2) with stderr summary
    8. dispatch on --by:
        let any_report = match cmd.by {
            AggregateKey::Tool => AnyAggregateReport::Tool(
                aggregate_by_tool(&reports, &episodes_vec)
            ),
            AggregateKey::McpServer => AnyAggregateReport::McpServer(
                aggregate_by_mcp_server(&reports, &episodes_vec)
            ),
            AggregateKey::Day => AnyAggregateReport::Day(
                aggregate_by_day(&reports, &episodes_vec, cmd.low_util_threshold)
            ),
            AggregateKey::Model => AnyAggregateReport::Model(
                aggregate_by_model(&reports, &episodes_vec)
            ),
        };
    9. apply --limit if > 0 (truncate any_report's inner buckets vec)
    10. render based on --export:
        let output = match cmd.export {
            Md   => format::aggregate_md::render(&any_report, &cmd),
            Json => serde_json::to_string_pretty(&any_report)?,
            Csv  => format::aggregate_csv::render(&any_report)?,
            Html => format::aggregate_html::render(&any_report, &cmd, version)?,
        };
    11. write to --output file OR stdout
    12. if failure_count > 0: stderr "aggregated N of M sessions (M-N failed)"
}
```

### 7.2 `load_and_analyze` helper

Same shape as `cmd::list::analyze_one` — load adapter session, derive episodes, run analyzer, return `(AnalysisReport, Episodes)`. Reused logic, not copy-pasted (factor into a shared module if it doesn't already exist).

### 7.3 Fail-soft + exit codes (per D-10)

| Situation | Exit | Stderr |
|---|---|---|
| All sessions parsed successfully | 0 | (no warning) |
| Some succeed, some fail | 0 | per-failure warning + final summary line |
| All sessions fail | 2 (DataError) | per-failure warning + final summary |
| Zero sessions in window | 0 | "no sessions matching --since=..." |
| `--root` doesn't exist | 1 (UserError) | "session root not found: <path>" |

## 8. Renderers

### 8.1 Markdown (`cmd::format::aggregate_md`)

Outer enum dispatcher pattern:

```rust
pub fn render(report: &AnyAggregateReport, cmd: &AggregateCmd) -> String {
    let mut out = String::new();
    write_header(&mut out, report);
    match report {
        AnyAggregateReport::Tool(r) => render_tool_table(&mut out, r),
        AnyAggregateReport::McpServer(r) => render_mcp_table(&mut out, r),
        AnyAggregateReport::Day(r) => render_day_table(&mut out, r, cmd.low_utilization_threshold),
        AnyAggregateReport::Model(r) => render_model_table(&mut out, r),
    }
    out
}
```

Per-key table shapes (column orders fixed; numeric right-aligned in HTML — markdown doesn't really support alignment but rendering is consistent left-align):

```
By tool:        | Tool | Source | Calls | Success | Fail | Total | p50 | p95 | Sessions |
By mcp-server:  | Server | Tools | Calls | Failures | Total | Sessions |
By day:         | Date | Sessions | Wall | Tool time | Out tokens | Utilization |   (⚠ prefix on low rows)
By model:       | Model | Sessions | Turns | Out tokens | Total wall |
```

Header (always emitted):

```markdown
# agentprof aggregate

- By: tool
- Window: --since 30d
- Sessions: 47 of 49 (2 failed; see stderr)
- Total wall-clock time: 12m 34s
- Generated by agentprof v0.1.0 on 2026-06-01T12:00:00Z
```

### 8.2 JSON (`cmd::format::aggregate_json`)

Just `serde_json::to_string_pretty(&any_report)`. The `#[serde(tag = "by")]` discriminator on `AnyAggregateReport` makes the JSON self-describing:

```json
{
  "by": "tool",
  "data": {
    "by": "tool",
    "since": "PT2592000S",
    "session_count": 47,
    "failure_count": 2,
    "total_wall_duration": "PT754S",
    "buckets": [ { "name": "bash", "source": ..., ... }, ... ]
  }
}
```

(Note: serde tag layout depends on whether we use `#[serde(tag = "...")]` (internal) or `#[serde(tag = "...", content = "...")]` (adjacent). Choose adjacent for cleaner separation between discriminator and payload.)

### 8.3 CSV (`cmd::format::aggregate_csv`)

Uses new `csv = "1"` workspace dep. One CSV per `--by` key with different column schemas:

```csv
# By tool:
name,source,call_count,success_count,failure_count,total_duration_ms,p50_ms,p95_ms,session_count
bash,Builtin,142,135,7,12340,80,1200,12
mcp__github__create_pr,"Mcp:github",3,3,0,5400,1700,2100,2

# By day:
date,session_count,wall_ms,tool_ms,output_tokens,utilization_pct,is_low_utilization
2026-05-30,3,18500,4200,1100,22.7,false
2026-05-31,5,67400,8100,2200,12.0,true     # marked is_low_utilization=true
```

CSV does NOT include the header metadata (sessions, window, etc.) — only the bucket rows. Header info goes to stderr as a `# aggregated N sessions...` comment line which the user can pipe or ignore.

### 8.4 HTML (`cmd::format::aggregate_html`)

Reuses M1.6.4's askama 0.16 infrastructure. New template `templates/aggregate.html` (separate from `report.html` — different content). Reuses M1.6.4's `styles.css` (already supports tables + warn color).

Layout:

```html
<header>
  <h1>agentprof aggregate</h1>
  <div class="meta">By: tool · Window: 30d · Sessions: 47 of 49 (2 failed) · Total wall: 12m 34s</div>
</header>

<section id="buckets">
  <table>
    <thead><tr><th>...</th></tr></thead>
    <tbody>
      {% for bucket in buckets %}
      <tr {% if bucket.is_low_utilization %}class="warn-row"{% endif %}>
        <td>{{ bucket.name }}</td>
        ...
      </tr>
      {% endfor %}
    </tbody>
  </table>
</section>
```

`.warn-row` CSS class colors the row background pale yellow (already in `styles.css`'s `.warning-line` class — extend or rename).

### 8.5 What's NOT done (per D-3)

- `--export tui` is NOT in `AggExportFormat` enum. Clap rejects with "invalid value 'tui'". A short message in the cli README says "TUI export coming in M1.6.3 with watch mode."

## 14. Risks & follow-ups

### 14.1 Risks (with mitigations)

| Risk | Mitigation |
|---|---|
| Memory: holding N AnalysisReport + N Episodes in RAM | Estimated 1-2 MB for 100 sessions × ~10 KB; well within budget. If users hit 1000+ session windows, follow-up could stream |
| Percentile pool size: 1000+ calls per tool × 100 sessions = 100K data points | sort + index is O(n log n); negligible for our scale |
| Per-session failure cascading | Per-session graceful; failures logged + counted; same pattern as `list` |
| CSV escaping edge cases (commas, quotes in tool names) | `csv` crate handles escaping; verify with a unit test using a tool name containing `","` and `'\n'` |
| HTML XSS from session data | askama auto-escapes `.html` extension; verified by M1.6.4 (same template engine) |
| Generic `AggregateReport<B>` rustdoc/clippy quirks | Constructor + Bucket trait kept simple; PhantomData not needed |
| Multiple-model sessions get one bucket (per D-12) | Documented in ADR-0008; future work could split via mode_segments |
| Day boundary at UTC midnight may surprise users in non-UTC timezones | Documented in cli README; future flag `--timezone` if needed |
| Empty bucket (e.g. `--by mcp-server` on sessions with no MCP calls) | Renderer emits "(no buckets)" placeholder; not an error |

## 16. Glossary

- **AggregateReport<B>**: generic data type carrying aggregation metadata + per-bucket data of type B
- **AnyAggregateReport**: serde-tagged enum wrapping `AggregateReport<X>` for one of the 4 bucket types; used at the CLI/serde boundary
- **Bucket**: one row in the aggregate output; e.g. `ToolBucket` for `--by tool`
- **Utilization**: `total_tool_duration / total_wall_duration × 100`, expressed as percentage. Low utilization (`< 20%`) suggests the agent is mostly thinking / waiting and tools are running rarely. High utilization (`> 50%`) suggests tools dominate the time budget
- **Session model** (per D-12): the model active at the first turn of a session; simple representative value when a session uses multiple models
- **First-turn model**: `report.turn_summary[0].model` (None-skipped)
